# mnemonic-toolkit bug hunt

**Audit date** — November 19, 2026

Revision `9069ad83`. The inventory contains **37 findings**: one Critical, 11 Important, 21 Minor and four Nit. Eighteen are previously filed defects reproduced here. Start with C1, I1, and I2. C1 affects disclosure of a complete seed. I1 affects the quorum encoded in the wallet. I2 and I3 affect whether a backup reaches storage. Severity is proposed for the implementing agent. The observations below are from unmodified code. Formal two-direction triage and post-fix testing are still open.

## C1 · Critical · SeedQR writes the complete seed into a publicly readable file

On Unix, `seedqr encode --from phrase=- --json-out FILE` created a new regular file with mode **0644** under umask 022. It contained both the mnemonic and its SeedQR digits, exited 0, and emitted empty stderr. Decode uses the same file-creation primitive. The manual at `docs/manual/src/40-cli-reference/41-mnemonic.md` even demonstrates decoding to `/tmp/decode.json`. Its worked seed is public, but using the same recipe for an actual wallet in a shared directory makes the seed readable by other local users. No recovery puzzle or access to the wallet hardware is required. No real wallet was used in this audit.

**Fix and regression.** In `cmd/seedqr.rs::emit_encode_output` and `emit_decode_output`, create secret regular files owner-only on Unix from the first open. Combine this with the replacement strategy in I3 so replacing an existing 0644 file also yields private permissions. Use a private directory in the manual example. Run both CLI directions under umask 022 and assert mode 0600 on fresh and replaced files, valid JSON, and empty stdout. Preserve intentional stream destinations where supported. Other secret JSON writers in `cmd/{seed_xor,slip39,electrum_decrypt,final_word}.rs` also use ordinary file creation and deserve the same permissions test. Some already emit a warning after writing.

## I1 · Important · A conflicting Coldcard header silently changes the spending quorum

Take `crates/mnemonic-toolkit/tests/export_wallet/coldcard_multisig_2of3_wsh.txt` and pipe it to `mnemonic import-wallet --format coldcard-multisig --blob - --json`. The control emits a 2-of-3 descriptor. Append one line, `Policy: 1 of 3`, and repeat. The command still exits 0, now emits `sortedmulti(1,...)`, and gives only the ordinary watch-only notice. This is an ambiguous input with two incompatible policies. Choosing the final one changes both the spending rule and derived addresses.

**Fix and regression.** In `wallet_import/coldcard_multisig.rs::parse_text`, check a second singleton policy against the parsed first value before assignment. Refuse a conflict with both line numbers before creating any envelope. Apply the same check to conflicting singleton script formats and global XFPs. Repeated per-cosigner derivations are part of the format and must continue to work. Exercise explicit and auto-detected imports and both header orders. Assert nonzero exit and empty stdout for a conflict and retain the original fixture as a positive control.

## I2 · Important · Failed writes of derived secrets return success

With the public test phrase (eleven `abandon` words followed by `about`) on stdin, `derive-child --from phrase=- --application hex --length 16 --index 0` normally writes 33 bytes. `convert --from phrase=- --to entropy` writes 42. With stdout redirected to a fresh regular file, the child process limited to zero output-file bytes via `RLIMIT_FSIZE`, and `SIGXFSZ` ignored, **both exited 0 with an empty file**. Both also exited 0 with a pipe whose reader had closed. The regular-file case directly affects callers that use success to mark a backup complete.

**Fix and regression.** Propagate payload writes using the existing I/O error type and flush before reporting successful delivery. Start at `cmd/derive_child.rs:306` and the plaintext output loop in `cmd/convert.rs:1251`. The same discarded-write idiom occurs in the card printer in `cmd/bundle.rs`, the result printer in `cmd/verify_bundle.rs`, and `cmd/gui_schema.rs`. Test each output mode with a writer that accepts a prefix and then errors, plus one that fails only at flush. Keep secret values out of diagnostics.

## I3 · Important · A failed SeedQR replacement destroys the previous backup

The C1 encode command produced a valid 270-byte JSON file. Repeating it against the same path with an eight-byte `RLIMIT_FSIZE` and ignored `SIGXFSZ` returned exit 1, but the original backup had already been replaced by eight bytes of incomplete JSON. This differs from I2 because the command correctly reports an error while destroying the existing file.

**Fix and regression.** Replace the direct `std::fs::write` in both SeedQR emitters with a private temporary file in the destination directory for regular-file output. Finish writing and checking the temporary file before renaming it over the destination. Exercise the same write limit against an existing file with known content and require byte-for-byte preservation on failure, cleanup of the temporary file, and valid JSON after a successful retry. Check the other direct regular-file writers before sharing the fix with them.

## I4 · Important · BIP-85 accepts a non-master xprv as its master

Use the published BIP-32 vector beginning `xprv9uHR` from the vendored bitcoin crate's `src/bip32.rs` (the child at `m/0'`). Pass it on stdin to `derive-child --from xprv=- --application hex --length 16 --index 0`. It exits 0 and emits a child secret. The derive-child specification defines the source as the master xprv. Starting the application path below an existing child derives a different recovery tree.

**Fix and regression.** In the `NodeType::Xprv` arm of `cmd/derive_child.rs::run`, validate depth zero before passing the decoded key to the BIP-85 engine. Refuse the depth-one fixture with empty stdout and a diagnostic naming the master-key requirement. Retain the depth-zero BIP-85 vectors and phrase path.

## I5 · Important · An environment value can silently switch the source wallet to stdin

Set `HUNT_FROM=-`, supply the public test phrase on stdin, and use `--from phrase=@env:HUNT_FROM`. Both `derive-child --application hex --length 16 --index 0` and `convert --to entropy` succeeded. The requested environment value was an invalid one-character phrase. Both commands derived from the unrelated stdin phrase instead.

**Fix and regression.** Record whether the original primary source token was a literal dash before calling `resolve_env_sentinels` in `cmd/derive_child.rs` and `cmd/convert.rs`. Use that same decision for both single-stdin validation and the eventual read. Mirror the existing passphrase handling. Test the environment-dash case with a reader that fails if touched and assert invalid phrase, then test a literal command-line dash and an environment variable containing a valid phrase as positive controls.

## I6 · Important · A single stop-sign word error makes an intact Word Card unreadable

Encode the public `MK1` constant in `tests/cli_word_card.rs` using `word-card --from "$card" --parity-words 4 --json`. The sole card has 92 words. Feed that word list to `word-card --decode --json -`. The original succeeds. Changing **only the final word** from `shed` to `stem` returns exit 2, “uncorrectable”. Changing it to `torch` reports multiple indels. The payload, header, four parity words, and creation ledger are all intact.

**Fix and regression.** In `crates/wc-codec/src/pipeline.rs::decode`, the tail marker supplies an 11-bit count that wins over the independently checked ledger. The stop checksum covers the preceding stream and does not authenticate the count itself. On disagreement, try plausible geometry from validated ledger records and evaluate recovered candidates with the existing RS and payload integrity checks. Return only a unique verified payload. Retain valid extension, truncation and indel semantics. Test both final-word substitutions, exact recovered payload and bit count, and the existing lost-tail cases. This is a recovery fix and needs codec review before implementation.

## I7 · Important · Mixed Word Card input silently discards positional words

With the valid word list from I6 on stdin, `word-card --decode --json nonsense -` exits 0 and emits the same recovery as `--decode --json -`. Any presence of a dash makes `cmd/word_card.rs::collect_words` ignore *every* other argument. A user can submit two sources and believe that both contributed to the recovery.

**Fix and regression.** Require the dash to be the sole positional input when using stdin. Reject mixed or repeated dashes before reading. Test a valid card on stdin with an extra positional token on either side and require nonzero exit and empty stdout. Preserve the quoted whole-card and multiple-word positional forms.

## I8 · Important · Address range validation allocates 8 GiB before deriving the first address

Using the public xpub in `tests/cli_addresses.rs`, `addresses --address-type p2wpkh --count 1` succeeds under a 256 MiB address-space limit. With the same input, `--count 2147483648` aborts with SIGABRT and “memory allocation of 8589934592 bytes failed”. This was measured with core dumps disabled and without allocating 8 GiB. Even the default unit suite's `ceiling_boundary_unit` calls the allocating branch.

**Fix and regression.** Make `cmd/addresses.rs::resolve_indices` return range bounds. Iterate them per chain. Stream the text and JSON rows or enforce an explicit documented batch limit before collecting either indices or output rows. Merely removing the index vector leaves the second allocation in the rows collection. Test the ceiling by inspecting bounds without iteration, a one-address range at the highest valid index, the first invalid index, and a broken output writer that terminates a large request promptly.

## I9 · Important · The compare-cost help example fails when copied

`compare-cost --miniscript 'or_b(pk(A), pk(B))'` exits 2 with a Miniscript type error. The example is printed by `--help`. Changing the second branch to `s:pk(B)` runs successfully and emits the cost comparison.

**Fix and regression.** In `cmd/compare_cost.rs::CompareCostArgs` replace the example with the executed `or_b(pk(A),s:pk(B))`. Exercise the expression taken from help through the CLI and assert exit 0. Grade follows the repository rule for failing printed examples.

## I10 · Important · Derive-child help names the wrong recovery path

`derive-child --help` assigns `hd-seed` to application 32. The implementation `bip85.rs::format_hd_seed_wif` derives at application **2** and renders a compressed WIF. Application 32 is the separate xprv operation. Reimplementing recovery from that help gives different key material. The same help says dice is refused and lists only 12/18/24-word mnemonics. A 100-roll, six-sided request and a 15-word request both succeeded in the probes.

**Fix and regression.** Correct the application descriptions in `cmd/derive_child.rs::DeriveChildArgs`: hd-seed uses `m/83696968'/2'/index'` and emits WIF, xprv uses application 32, dice is implemented, and mnemonic lengths are 12/15/18/21/24. Keep the current derivation and pinned test vectors. Check help and generated man-page text against those vectors.



## I11 · Important · The CompactSeedQR manual examples both refuse their input

The two worked commands in `docs/manual/src/40-cli-reference/41-mnemonic.md:2848` and :2859 put the public test phrase or numeric SeedQR directly in argv. As printed, each exits 2 before parsing and produces zero bytes of the promised output. Passing the same values on stdin with `--from phrase=-` and `--from seedqr=-` produced the expected 32 hexadecimal characters and 12-word phrase respectively. The QR-generation pipeline in the same section teaches the same rejected input form.

**Fix and regression.** Rewrite these examples to pass the fixture on stdin with `printf '%s' ... | mnemonic seedqr ...`, retaining the compact variant and downstream output pipeline. Run the exact published commands in the manual transcript tests against a binary with its normal argv policy. Leave the argv guard enabled.

## M1 · Minor · addresses waits for a passphrase it already knows it must reject

Inspected toolkit revision `9069ad83`. In `crates/mnemonic-toolkit/src/cmd/addresses.rs`, `run` resolves the passphrase at line 148 before checking the xpub/passphrase conflict at line 165. A caller keeping stdin open can wait indefinitely for an input that cannot affect the verdict. Closing an empty stream even prints a warning that the command is proceeding with an empty passphrase immediately before it refuses.

### Evidence

Ran the following arguments against the checkout's existing debug binary with a pipe as stdin.

    target/debug/mnemonic addresses --from xpub=unused --address-type p2wpkh --passphrase-stdin

With the writer open and silent, the process was still waiting after one second. Sending a newline and closing the pipe produced empty stdout, the empty-passphrase warning, the xpub/passphrase refusal, and exit 1. The placeholder key is intentional. The conflict depends only on the source kind and precedes key parsing. The existing binary was not rebuilt for this check.

### Proposed fix for the implementing agent

In `addresses::run`, move both existing xpub option checks (nonzero account, then passphrase presence) from the xpub match arm into an `if from.node == NodeType::Xpub` block immediately after the single-stdin conflict check. Reuse the existing diagnostics and ordering. This makes the decision before resolving either input, including environment-variable lookup, and preserves the more specific dual-stdin diagnostic. Leave key parsing and network validation in the match arm.

Add a regression test invoking the generic handler with a reader whose read method panics. Supply an inline xpub source and exercise both passphrase spellings (`--passphrase-stdin` and `--passphrase -`). Assert the existing xpub/passphrase refusal and empty stdout and stderr from the handler. The current code reaches the reader. The fixed code should return the conflict without touching it. Retain the existing valid seed-source passphrase coverage.

## M2 · Minor · Coldcard cosigner count wraps before validation

Append 256 copies of the last cosigner row to the I1 fixture, leaving the policy at 2 of 3. The parser gets past the policy-count check with 259 entries and eventually exits 2 with “more than 256 keys (placeholder @N overflow)”. The downstream refusal prevents a wrong wallet. In `wallet_import/coldcard_multisig.rs:324`, change the predicate to `cosigners_raw.len() != usize::from(policy.n)`. Assert the refusal names the declared 3 and actual 259 before processing any xpub.

## M3 · Minor · SeedQR language selection produces a misleading refusal

Supply eleven groups of `0000` and one `0003` on stdin to `addresses --from seedqr=- --address-type p2wpkh --count 1`. With English it returns one address. With Japanese it claims word zero was unknown even though the caller supplied only numeric indices. The handler decodes indices into English words, then reparses those words in Japanese. Help advertises language selection for SeedQR while the SeedQR library defines an English-only format. Preserve the English-only contract: reject incompatible language selection explicitly before reading and describe the limitation in help. Keep non-English phrase input working. Cover the corresponding SeedQR branches of restore, bundle and verify-bundle when reconciling their help.

## M4 · Minor · Import help describes shipped parsers as unavailable

`mnemonic import-wallet --help` says “BSMS Round-2 only”, lists other formats as stubs, and documents only two possible JSON source formats. The unmodified Coldcard control in I1 actually imports and returns its own source format. Replace the historical rollout prose in `main.rs:131` and `cmd/import_wallet.rs` with current behavior. Derive the advertised format list from the CLI enum where practical. Check the resulting help alongside successful explicit and auto-detected fixture imports.

## M5 · Minor · The dice allocation regression can pass without running the CLI

Under a 768 MiB hard address-space limit, the ignored `bughunt_tk_15_dice_huge_length_is_refused_cleanly` passed. Its shell wrapper attempts to set a roughly 4 GB limit and only executes the CLI if that succeeds. A setup failure is a normal nonzero shell exit and satisfies the test. A direct run with a 256 MiB limit actually aborted after requesting 48,000,000,000 bytes. In `tests/bughunt_s4.rs`, set a child limit no greater than the existing hard limit, distinguish setup failure, and require the agreed toolkit exit code **and** dice-specific diagnostic. The underlying dice bug is separately recorded below.

## N1 · Nit · Standard SeedQR module documentation understates supported lengths

The top of `crates/mnemonic-toolkit/src/seedqr.rs` says 12 and 24 words only. Its standard decoder accepts 48, 60, 72, 84 and 96 digits. Amend the module docs to list all five word counts for standard SeedQR and 12/24 for compact. Keep the existing length tests.

## Runnable evidence for C1 and I1–I3

Run this from the repository root on Linux with a built debug binary. It uses the public BIP-39 test mnemonic and writes only temporary files beneath the repository's target directory. The output shows the observed values for comparison after the fix.

```python
import json
import resource
import signal
import subprocess
import tempfile
from pathlib import Path

binary = Path("target/debug/mnemonic").resolve()
phrase = "abandon " * 11 + "about\n"
fixture = Path("crates/mnemonic-toolkit/tests/export_wallet/coldcard_multisig_2of3_wsh.txt")

def run(args, data, **kwargs):
    return subprocess.run(
        [binary, *args], input=data, text=True, stderr=subprocess.PIPE,
        **kwargs,
    )

def file_limit(n):
    def apply():
        resource.setrlimit(resource.RLIMIT_FSIZE, (n, n))
        signal.signal(signal.SIGXFSZ, signal.SIG_IGN)
    return apply

with tempfile.TemporaryDirectory(dir="target") as tmp:
    dest = Path(tmp) / "seed.json"
    for verb, source, data in [
        ("encode", "phrase=-", phrase),
        ("decode", "seedqr=-", "0000" * 11 + "0003"),
    ]:
        if dest.exists():
            dest.unlink()
        args = ["seedqr", verb, "--from", source, "--json-out", str(dest)]
        r = run(args, data, stdout=subprocess.PIPE, umask=0o022)
        assert r.returncode == 0 and json.loads(dest.read_text())["phrase"] == phrase.strip()
        print("C1", verb, oct(dest.stat().st_mode & 0o777), "stderr", repr(r.stderr))

    before = dest.read_bytes()
    r = run(args, data, stdout=subprocess.PIPE, preexec_fn=file_limit(8))
    print("I3", r.returncode, "bytes remaining", dest.stat().st_size,
          "prior backup preserved", before == dest.read_bytes())

    for args in [
        ["derive-child", "--from", "phrase=-", "--application", "hex", "--length", "16", "--index", "0"],
        ["convert", "--from", "phrase=-", "--to", "entropy"],
    ]:
        sink = Path(tmp) / "output"
        with sink.open("wb") as out:
            r = run(args, phrase, stdout=out, preexec_fn=file_limit(0))
        print("I2", args[0], "exit", r.returncode, "bytes written", sink.stat().st_size)

for extra in ["", "\nPolicy: 1 of 3\n"]:
    r = run(["import-wallet", "--format", "coldcard-multisig", "--blob", "-", "--json"],
            fixture.read_text() + extra, stdout=subprocess.PIPE)
    descriptor = json.loads(r.stdout)[0]["bundle"]["descriptor"] if r.stdout else ""
    print("I1", "conflicting" if extra else "control", "exit", r.returncode,
          "threshold", descriptor.partition("sortedmulti(")[2].partition(",")[0])
```
