2. #51: should `inspect` report every ms1 given, or refuse a second one? (The test accepts either; it rejects only silent ignoring.)
3. X1: refuse a mixed-case chunk outright (the scratch fix), or use BIP-93's optional "characters with incorrect case, as erasures" and correct it, flagged as a repair?
4. X2: resolve `@env:VAR` for `--ms1` on `repair` and `inspect` for parity with `verify-bundle`/`bundle`, or leave it unsupported (the GUI already routes around it)? The "drop the GUI claim" half does not apply, see the X2 row.
5. X3: where does share correction live (toolkit-only as in the scratch fix, or ms-codec's `decode_with_correction` so `ms repair` gains it)? Which exit code for a corrected share (the test asserts 4, the existing ms1 correction exit) and for an already-valid share (asserts 0)?
6. X4: output case of a corrected all-capitals card (lowercase today; the test accepts either).
7. X5: join (a card wrapped over lines) or refuse (name the second line) when `--ms1 -` sees several non-empty lines whose first line is not a valid card?
