# `mt` (mt-cli) reference

<!-- cspell:ignore txid wtxid bitcoind sats umask scriptSig Tails -->

The standalone CLI for the mt1 format (mnemonic-transaction / mt-codec).
`mt` turns an **already-signed** Bitcoin transaction into engravable
form and reads it back: `mt1` codex32 strings to engrave by hand, or,
with `encode --qr`, a `tx:` record that [`me sysw pack`](#me-sysw-pack)
packs for a SeedHammer II. It builds nothing, signs nothing and
broadcasts nothing. Five verbs: [`encode`](#mt-encode),
[`decode`](#mt-decode), [`verify`](#mt-verify),
[`inspect`](#mt-inspect) and [`repair`](#mt-repair). `decode`, `verify`
and `inspect` also correct substituted characters themselves; `repair`
prints the corrected strings so damaged plates can be re-cut (see
[Which tool owns which verb](#which-tool-owns-which-verb)).

This chapter describes `mt 0.2.0`, built from mnemonic-transaction's
default branch. Every subcommand accepts `--help` (`-h` prints a
one-line summary of each flag, `--help` the full text); each Flags table
quotes the summary.

:::danger
An mt1 set, a `tx:` record and the hex `mt decode` prints are all
**bearer** material: anyone holding them can broadcast the transaction.
The examples below use a public regtest transaction from
mnemonic-transaction's test fixtures (`crates/mt-cli/tests/fixtures/p5_base.json`,
its `finalized_psbt_b64`); its coins exist only on that test chain.
:::

## Conventions

| Topic | Rule |
|---|---|
| Input | From `--in <PATH>` or stdin, **never an argument**. A transaction or an mt1 string on argv is refused before the parser runs (below). `encode` reads a finalized PSBT (binary or base64) or a raw transaction in hex; the other three read mt1 strings, one per line, whitespace inside a line stripped |
| Streams | stdout is the artifact (the strings, the hex, or `inspect`'s report); everything a person must see goes to stderr. `encode`'s report, legend and warnings are on stderr; so are `decode`'s report and `verify`'s verdict |
| Node | `encode`, `decode` and `inspect` consult a local node through `bitcoin-cli` automatically when one answers (it already holds the RPC URL, cookie and network); `verify` never does. `--bitcoin-cli /nonexistent` forces the offline path, and every example below uses it. With no node, the report marks what it could not check `UNKNOWN` and shows addresses as mainnet |
| Output files | `mt encode` refuses to write into a stdout that is a group- or world-readable file (`>` under the usual `umask` 022 makes one) unless `--allow-world-readable`; `--out <PATH>` creates the file owner-only (`0600`) and overwrites it. `mt decode` only warns about the same destination |
| Corrections | Up to 4 substituted characters per string are corrected while reading, and the correction is reported. A missing or extra character, or a missing string, cannot be corrected: every string of the set is required |
| Grouped strings | `--group-size` output (and `--elide-prefix` output) is read back by `decode`, `verify` and `inspect` unchanged |

### Bearer material never goes on argv {#mt-argv-guard}

```sh
$ mt verify mt1pgej7qqgqqqqgqqqqqqqypfx5rtme6rurwj0eyn82d5t9cde9ac74du7p7kvy7jmv7shd7r68ewudpmt4zggf
mt verify: REFUSED — §8.2f, an mt1 set was passed as a command-line argument (88 characters)
...
  Then re-run: mt <verb> < file
  TO PURGE WHAT ALREADY LEAKED -- match on the COMMAND, never on the secret, ...
            zsh:    fc -W; sed -i '/\bmt verify\b/d' "$HISTFILE"; ...
            bash:   history -w; sed -i '/\bmt verify\b/d' "$HISTFILE"; history -c; history -r
            fish:   history clear-session
$ echo $?
1
```

The refusal never prints the argument back, and it prints a per-shell
recipe to purge the leaked line from history. `--allow-argv-secret`
(every verb) admits the material and reads it as if it had come from
`--in`; use it only where argv is not a public channel (a single-user
air-gapped box, an amnesic Tails session).

## `mt encode`

Turn a signed transaction into engravable form. Default: mt1 strings.
`--qr`: one `tx:` record (the final transaction as lowercase hex) for
[`me sysw pack`](#me-sysw-pack), which the SeedHammer II engraves as QR
plates.

### Synopsis

```sh
mt encode [--in <PATH>] [--out <PATH>] [--from <ID>] [--to <ID>] [--to-label <TEXT>]
          [--input-value <INDEX:AMOUNT>]... [--group-size <N> [--separator <S>]] [--elide-prefix]
          [--qr] [--quiet] [--bitcoin-cli <PATH>]
```

### Flags

| Flag | Purpose |
|---|---|
| `--in <PATH>` | Read the transaction from a file. Defaults to stdin |
| `--out <PATH>` | Write the artifact to a FILE, **created owner-only (0600)**, instead of stdout. It overwrites an existing file |
| `--from <ID>` | Wallet id or fingerprint for the legend's `FROM` line |
| `--to <ID>` | Wallet id or fingerprint for the legend's `TO` line |
| `--to-label <TEXT>` | Free-text destination label. The legend marks it `LABEL ONLY, unverified`: nothing can check it against the transaction |
| `--input-value <INDEX:AMOUNT>` | An input's value, as `<index>:<amount>` (amount in BTC, e.g. `0:0.05`). Repeatable, one per input. Needed for a fee from a raw transaction with no node; the report then marks the fee `CLAIMED` and the inputs `OPERATOR-ASSERTED` |
| `--group-size <N>` | Group the output every N characters, for hand engraving. Refused with `--qr` |
| `--separator <S>` | Separator to use with `--group-size`. **Whitespace only, never a newline.** [default: " "] |
| `--elide-prefix` | Emit the set's invariant 8 characters on the first string only. Refused with `--qr`; [`me sysw pack`](#me-sysw-pack) refuses elided strings |
| `--qr` | Emit the `tx:` RECORD for `me sysw pack` — the SeedHammer II path — instead of `mt1` strings to engrave by hand |
| `--allow-argv-secret` | Proceed even though bearer material was passed on the command line (§8.2f). See [above](#mt-argv-guard) |
| `--allow-world-readable` | Proceed even though stdout is a world-readable file (§8.2h) |
| `--quiet` | Suppress the inspection report. **Warnings and refusals are never suppressed**, on any verb |
| `--json` | Machine-readable report. **Refused on `encode`** (exit 1): use `mt inspect --json` |
| `--bitcoin-cli <PATH>` | Path to `bitcoin-cli`, for a binary not on `PATH` [default: bitcoin-cli] |

`encode` refuses a PSBT that is not finalized (`2 of 2 inputs are not
finalized`), input that does not parse as a transaction, a 64-character
txid given in place of a transaction, and a transaction whose inputs do
not carry a signature shaped like one that commits to the outputs. `mt`
has no script engine: it checks the witness **shape**, not the
signature, and says so.

### Worked example

```sh

$ mt encode --in tx.psbt.b64 --out strings.txt --bitcoin-cli /nonexistent
```

strings.txt` under the default `umask` is refused (exit 1) and the
refusal lists four ways on.

## `mt decode`

Read `mt1` strings back and emit BROADCASTABLE HEX on stdout. The report
goes to stderr.

### Synopsis

```sh
mt decode [--in <PATH>] [--quiet | --json] [--bitcoin-cli <PATH>]
```

### Flags

| Flag | Purpose |
|---|---|
| `--in <PATH>` | Read the strings from a file. Defaults to stdin |
| `--allow-argv-secret` | Proceed even though bearer material was passed on the command line (§8.2f) |
| `--transaction <PATH>` | Listed by `mt decode --help`, but `verify` only: **`decode` refuses it** (exit 1, `--transaction has no meaning for decode`), whatever the path |
| `--quiet` | Suppress the report. Warnings and refusals are never suppressed (the no-node warning still prints) |
| `--json` | Machine-readable report, on stderr. `--json` with `--quiet` is refused (they contradict each other) |
| `--bitcoin-cli <PATH>` | Path to `bitcoin-cli`. Pointing this at something absent forces the OFFLINE path [default: bitcoin-cli] |

### Worked example

```sh
$ mt decode --in strings.txt --bitcoin-cli /nonexistent 2>/dev/null | cut -c1-64
0200000000010293506bde743e0dd27e4933a9b45970dc97b8f55bcf07d6613d
```

The hex is the transaction `encode` read, byte for byte. `mt decode >
tx.hex` into a file of mode `0644` warns (it does not refuse: that is
the ordinary command on a default machine) and tells you to `chmod 600`
it.

## `mt verify`

Check a set of `mt1` strings — structurally, and never asking a node.
The verdict goes to stderr; stdout is empty. Type the strings back from
the steel and verify that file, not the file `encode` wrote.

### Synopsis

```sh
mt verify [--in <PATH>] [--transaction <PATH>]
```

### Flags

| Flag | Purpose |
|---|---|
| `--in <PATH>` | Read the strings from a file. Defaults to stdin |
| `--allow-argv-secret` | Proceed even though bearer material was passed on the command line (§8.2f) |
| `--transaction <PATH>` | Compare against a transaction, by FULL txid. Takes a **PATH** (a PSBT or raw-hex file), never the transaction itself |
| `--quiet` | Listed by `mt verify --help`, but **refused by `verify`** (exit 1, `--quiet has no meaning for verify`) |
| `--json` | Listed by `mt verify --help`, but **refused by `verify`** (exit 1); use `mt inspect --json` |
| `--bitcoin-cli <PATH>` | Listed by `mt verify --help`; `verify` never asks a node, so it has no effect [default: bitcoin-cli] |

### Worked example

```sh
$ mt verify --in typed-from-steel.txt
mt verify: OK — 9 chunks, set 0x4665e, transaction re-derives.

CORRECTION APPLIED. 1 chunk needed repair:
  chunk   2   1 of 4 symbols
              pos  31   read q, corrected to l

$ mt verify --in strings.txt --transaction tx.hex
mt verify: OK — 9 chunks, set 0x4665e, transaction re-derives.
  --transaction matches, on the full txid.

$ head -8 strings.txt > short.txt; mt verify --in short.txt
mt verify: REFUSED — §1.1, the set does not verify

  chunk 9 of 9 is missing
$ echo $?
1
```

## `mt inspect`

Report what is IN a set. Queries a local node AUTOMATICALLY if one is
reachable. The report goes to **stdout** (unlike `decode`'s); warnings
go to stderr. It also reads a transaction (a PSBT or raw hex) and
reports on that, with a warning that the bytes say nothing about which
plate they came from. A `tx:` record is refused: that is `encode --qr`'s
output, not an input.

### Synopsis

```sh
mt inspect [--in <PATH>] [--json] [--bitcoin-cli <PATH>]
```

### Flags

| Flag | Purpose |
|---|---|
| `--in <PATH>` | Read the strings from a file. Defaults to stdin |
| `--allow-argv-secret` | Proceed even though bearer material was passed on the command line (§8.2f) |
| `--transaction <PATH>` | Listed by `mt inspect --help`, but **refused by `inspect`** (exit 1, `--transaction has no meaning for inspect`) |
| `--quiet` | Listed by `mt inspect --help`, but **refused by `inspect`** (exit 1, `--quiet has no meaning for inspect`) |
| `--json` | Machine-readable report, on stdout |
| `--bitcoin-cli <PATH>` | Path to `bitcoin-cli`. Pointing this at something absent forces the OFFLINE path [default: bitcoin-cli] |

### Worked example

```sh
$ mt inspect --in strings.txt --bitcoin-cli /nonexistent 2>/dev/null
mt1 SET   9 strings, 1..9 all present, all begin mt1pgej7qqg
TX        4665e0aa2a97dee3e53fd2eaab0942abc0fef2339e730458ceedcda400d708c3
OUT       1 output(s)   (addresses shown as MAINNET — no node to ask)
            bc1q07h88fcj0j86excq5m9k97e26su7j5tdvldytq   7.99900000 BTC
FEE       UNKNOWN   (needs input values, which the transaction
          does not carry)
LOCKTIME  NO TIMELOCK                      current height unknown (no node)
INPUTS    2 input(s)
            d13d7cbbd0b32d3d…   UNKNOWN
            b6c8e4075b8481b7…   UNKNOWN
STATUS    UNKNOWN — no node reachable

$ mt inspect --json --in strings.txt --bitcoin-cli /nonexistent | head -5
{
  "txid": "4665e0aa2a97dee3e53fd2eaab0942abc0fef2339e730458ceedcda400d708c3",
  "txid_provisional": false,
  "strings": 9,
  "set_prefix": "pgej7qqg",
```

The fee is unknown here because the mt1 strings carry the final
transaction, which names its inputs but not their values; with a node
reachable `mt` fetches them.

## `mt repair`

Print the corrected `mt1` strings of a set, so damaged plates can be
re-cut. It reads the strings as `verify` does and prints them in chunk
order, in `encode`'s layout. **The strings are CORRECTED, not
verified**: a string damaged in more than 4 places can be "repaired"
into a different valid string, and the id check does not cover the
witness (the signatures). The notice goes to stderr; the strings go to
stdout, or to `--out`.

A partial set (some chunks missing) is printed too, headed `PARTIAL`
and `UNCHECKED`: nothing in it can be checked against the transaction
until every chunk is present. `repair` was added after `mt 0.2.0`
(SPEC_mt decision 1f, ruled 2026-11-28) and uses the constellation's
shared exit codes below, not the 0.2.0 table at the end of this chapter.
It ships in `mt` now; the reading of the 2026-11-28 ruling, pending
confirmation, is that it moves to `mnemonic repair` with the other
formats' repairs once that verb accepts `mt1`.

:::danger
**Keep the damaged plates.** Do not discard or re-use them until the
transaction has confirmed: they are the only evidence if a correction
was wrong. Running `mt verify` on plates re-cut from these strings proves
only that the re-cut matches these strings. `mt repair --out` refuses to
write over its own input for the same reason: the typed record of the
damaged plates is that evidence.

When the strings go to a file (`--out`, or stdout redirected), `repair`
ends with the bearer warning `encode` prints, but its last paragraph
differs: keep the file with the damaged plates, and destroy it only once
the plates are re-cut and the transaction has confirmed. `encode`'s says
to destroy it once the plates are cut and verified; `repair` never says
that, because a re-cut checked against these strings proves nothing more.
:::

### Synopsis

```sh
mt repair [--in <PATH>] [--out <PATH>] [--group-size <N> [--separator <S>]] [--elide-prefix]
          [--allow-world-readable]
```

### Flags

| Flag | Purpose |
|---|---|
| `--in <PATH>` | Read the strings from a file. Defaults to stdin |
| `--out <PATH>` | Write the corrected strings to a FILE, **created owner-only (0600)**, instead of stdout. It OVERWRITES, as `encode --out` does |
| `--group-size <N>` | Group the output every N characters, as `mt encode --group-size` does |
| `--separator <S>` | Separator to use with `--group-size`. **Whitespace only, never a newline**, as for `mt encode`: mt reads nothing else back [default: " "] |
| `--elide-prefix` | Drop `mt1` and the set's invariant 8 characters from every chunk but chunk 1, as `mt encode --elide-prefix` does for strings 2..n. By chunk number: a partial set without chunk 1 prints every line elided |
| `--allow-world-readable` | Proceed even though stdout is a world-readable file (§8.2h) |
| `--allow-argv-secret` | Proceed even though bearer material was passed on the command line (§8.2f). See [above](#mt-argv-guard) |

`repair` takes no `--json`, `--quiet`, `--transaction`, `--bitcoin-cli`
or `--offline` (usage, 64). The output channel is judged before any
input is read: a separator mt cannot read back (64), `--out` naming the
input file (8) and a world-readable stdout file (8).

### Exit codes of `mt repair`

| Code | Meaning |
|---|---|
| `0` | no correction applied, and every check passed (on a partial set: nothing was checked against the transaction) |
| `16` | a correction was applied, or a damaged copy of a chunk was set aside and must be re-cut; set only after every check has passed |
| `2` | the input is invalid: a complete set that does not re-derive its id, mixed sets, partial-set lengths no encoder writes, a string whose padding bits are not zero, an unreadable string in a partial set, or input that is no set. Nothing is printed, and a refusal after a correction is `2`, never `18` |
| `8` | refused: bearer material on argv, `--out` onto the input, a world-readable stdout file |
| `32` | added when a file or device fails (an input that cannot be read, an output that cannot be written) |
| `64` | usage: a flag `repair` does not take, a separator mt cannot read back |

A script that accepts a corrected set tests `[ $(( rc & ~16 )) -eq 0 ]`.

### Worked example

```sh
$ mt repair --in typed-from-steel.txt --out repaired.txt
mt repair: CORRECTED — 6 chunks, set 0x2dcf2, transaction re-derives its id.
  These strings are CORRECTED, not verified. BCH repaired 1 chunk. A string
  damaged in more than 4 places can be "repaired" into a different valid string,
  and the id check does not cover the witness (the signatures).
  KEEP the damaged plates. Do not discard or re-use them until this transaction
  has confirmed: they are the only evidence if a correction was wrong.
  Running mt verify on plates re-cut from these strings proves only that the
  re-cut matches these strings.

  string 1 of the input → chunk 1 of 6   (2 symbols corrected)

CORRECTION APPLIED. 1 chunk needed repair:
  chunk   1   2 of 4 symbols
              pos  41   read q, corrected to c
              pos  56   read q, corrected to d

WARNING: the strings went into repaired.txt — and they are BEARER, exactly like the plate.

  mt created that file mode 0600, so only its owner can read it today
  — that is what --out is for, and a shell redirect cannot do it.
  The mode still becomes dangerous the moment the file is copied,
  moved into a backup, or its parent relaxed. Wherever that is, anyone
  who reads it can broadcast this transaction: it is the engraving, in
  a form that copies itself.

  If it landed in a FILE, keep it with the damaged plates: it is the
  record of what mt corrected. Destroy it only once the plates are
  re-cut and this transaction has confirmed: `shred -u <file>` on
  Linux, `rm -P <file>` on macOS. Plain `rm` unlinks the name and
  leaves the bytes. And check it is not already in a backup, a sync
  folder, or your editor's undo history.
$ echo $?
16
```

## Exit codes

| Code | Meaning |
|---|---|
| `0` | success: every check passed (a correction, when one was applied, is reported on stderr) |
| `1` | refused or failed: every `REFUSED` (an argument carrying bearer material, a flag the verb does not take, an unfinalized PSBT, a set that does not verify, a world-readable stdout for `encode`), and a failed write to stdout (`mt: cannot write the output: <error>`) |
| `2` | usage error found by the argument parser (an unknown verb or flag, `--qr` with `--group-size`) |
| `64` | an argument that is not valid UTF-8, refused by position before anything is read |

A reader that closes the pipe early (`mt decode … | head -c 64`) only
stops the output: the exit code is the verb's own. These are the codes
of `mt 0.2.0`; they change when the constellation's shared exit-code
scheme (mnemonic-transaction PR #33) lands.

## Quirks

- `mt decode --help` lists `--transaction`, `mt verify --help` lists
  `--quiet` and `--json`, and `mt inspect --help` lists `--quiet` and
  `--transaction`, but those verbs refuse them (exit 1). `mt encode`
  lists and refuses `--json` the same way. `decode`, `verify` and
  `inspect` share one set of arguments, so each one's `--help` shows the
  flags of the other two; `verify --help` also lists `--bitcoin-cli`,
  which it never uses.
- Only full strings pack: `me sysw pack` takes plain `mt encode`
  output and `mt encode --qr` output, but refuses
  `--group-size` and `--elide-prefix` output (exit 4): pack the full,
  ungrouped strings.
- `mt decode`'s report is on stderr and `mt inspect`'s on stdout.
