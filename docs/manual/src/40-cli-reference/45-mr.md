# `mr` (mr-cli) reference

The standalone CLI for the Refugium mr1 format (mnemonic-refugium /
mr-codec). An mr1 card describes a whole set of wallets: one template
(a BIP-388 wallet policy), an epoch axis that moves its deadlines
forward, and a table of slots (rows) that change the template per
wallet. Each wallet of the set is a *member* (e, s): epoch e, slot s.
The card also carries the (0, 0) member as an md1 card.

This chapter mirrors mnemonic-refugium's `mr-cli`: the writers
`create` and `upgrade`, and the read-side verbs `verify`, `decode`,
`repair`, `member`, `address`, `current`, `units` and the heir's
`export`.

:::primer
A *slot* is a row of the card's slot table: slot 0 is the template as
written, and each further slot changes some of its units (switches a
branch off, shifts a deadline, adds a wait). An *epoch* moves every
deadline of the template forward by the card's delta, so the same slot
at a later epoch is a new wallet with later deadlines. `current` tells
you which epoch to use now; `member` and `address` hand out that member.
:::

Every subcommand below accepts `--help` (`-h`) for inline help. Each Flags table quotes `mr <verb> --help` verbatim.

## Conventions

| Topic | Rule |
|---|---|
| Card input | The positional `<mr1>...` is one card: a single `mr1` string, or every string of a chunk set, in order. A chunk set is always one card, never several |
| Checksums | Every reading verb **verifies only**: a string that is not a valid codeword is refused (`the mr1 checksum does not verify`), never corrected silently. Correction is `mr repair`'s job |
| Network | `--network <NETWORK>` is global: `main` (the default; `mainnet` is accepted as an alias), `signet`, `testnet` or `regtest`. It picks the address format, `xpub` or `tpub`, the tip anchor and the coin type. Any other value is a usage error |
| Tip | The tool never reads the machine's clock. Every verb that measures a deadline takes the chain tip as `--height H --time T` (the median time past, unix seconds; `--time` takes any u32) and prints `tip = <height>, ≈ <date>; this must be the current tip` first. On mainnet a tip whose height and time disagree with the release's anchor by more than 180 days is refused unless `--accept-tip`; off mainnet it only warns. `member --for-spend` runs no tip check, so recovery is never blocked by it: it prints only the tip line |
| Numbers | Printed numbers carry thousands separators (`1,260,000`), except in script text, command lines, flag values, indexes, epochs and hex ids |
| Streams | Results go to stdout; warnings go to stderr as `warning: …`; errors print as `mr: <message>`. A reader that closes the pipe early (`mr decode … \| head -1`) only stops the output: the exit code is the verb's own. Any other write error on stdout (a full disk, `> /dev/full`), from a verb or `--help`, prints `mr: cannot write the output: <error>` and exits 1. A stdout closed outright (`>&-`) behaves as `> /dev/null`: the output is discarded and the exit code is the verb's own |
| Secrets | `mr` never prints a private key, entropy or an ms1 seed string. It prints seed words in one case only: for each seed that `--seeds` gives as BIP-39 words, stderr carries `seed <n> read as <language>: <words>` once, so the words can be checked against the backup. Treat stderr as secret whenever `--seeds` holds words. A card argument that does not start `mr1` is never echoed: seed words (spaced or comma-joined), an ms1 string, an mk1 string or an md1 string is refused by every verb, naming only what it looks like, e.g. `a card argument looks like seed words (<n> words, not echoed): seeds go in --seeds, and a card is its mr1 strings`. `member`, `address` and `current` refuse any other non-`mr1` value the same way, quoting only a bare integer of at most 20 digits (the `--epoch`/`--slot` hint); `units` reads a non-`mr1` argument as a template: one with no `(` is never a template and is never quoted, only named by its kind (an extended private key, a WIF or base58 key, hex, seed words joined by any punctuation, or a bare word), and a template's parse error names a bad part by its character, never quoting it. A usage error never echoes a value at all (a phrase typed without its verb, as a flag's value, or as the `<lang>` of `--seed-language 1=<lang>`): it names the value by its position, and keeps the verb and flag names as they are. The command line itself (shell history, the process list) is outside `mr`'s reach |

### Exit codes

| Code | Meaning |
|---|---|
| `0` | success |
| `1` | refused or failed (a guardrail, a check, a key that does not fit) |
| `2` | usage error (unknown flag, bad value, missing argument); `mr repair`: nothing could be corrected |
| `5` | `mr repair` only: the strings were corrected |

### Keys and seeds

`verify`, `member` and `address` take the set's keys in one of these
forms. On a card whose Pubkeys TLV keys every seat, `member`, `address`
and `export` need neither `--keys` nor `--seeds`: every key comes from
the card (`member --as policy` still needs a seed or plate for a seat,
since a signer registers only a key it holds). On a card with a seat it
does not key, `member` or `address` given neither is a usage error
(exit 2), and `export` refuses it (exit 1).

| Form | Meaning |
|---|---|
| `--keys <mk1…>` | an mk1 plate (a chunked plate's strings in one value, separated by spaces) |
| `--keys '[fp/path]xpub'` | a record: a key in `verify`; in `member` and `address` it only confirms a seat that a seed supplies; `member --for-spend` refuses one |
| `--keys '@i=<key>'` | the key bound to seat `@i`, in the card's stored numbering |
| `--keys-file <file>` | one key per line (`@i=<card>` or the key alone), a chunked plate's strings on consecutive lines; blank lines and `#` comments are skipped |
| `--seeds <seeds>` | ms1 plates or BIP-39 words, comma-separated, seed 1 first |

## `mr verify`

Re-read an engraved card and check it against ids, keys or seeds. With
keys or seeds it prints the seat each one filled (`plate 2 → seat @2`,
with the seat check `sc:…`) and fails on a stub mismatch.

### Synopsis

```sh
mr verify [OPTIONS] <mr1>...
```

### Flags

| Flag | Purpose |
|---|---|
| `<mr1>...` | The card's strings (one, or each chunk of a chunked card) |
| `--network <NETWORK>` | Network: main (default; `mainnet` is accepted too), signet, testnet or regtest [default: main] |
| `--set-id <ID>` | Fails unless the card's set id is ID (hex) |
| `--digest <D>` | Fails unless the card digest is D (hex): proves this engraving |
| `--against <md1>` | Checks that member (0, 0) matches this md1 card (its strings in one value, separated by spaces) |
| `--keys <mk1…\|records>...` | Keys: mk1 plates (a chunked plate's strings in one value, separated by spaces) or `[fingerprint/path]xpub` records, each optionally `@i=`-bound |
| `--keys-file <file>` | A file of keys: one `@i=<card>` per line, chunked cards as consecutive strings |
| `--seeds <seeds>...` | Seeds: ms1 plates or BIP-39 words, comma-separated, in order (seed 1 first) |
| `--seed-language <n>=<lang>` | The wordlist of seed n: `<n>=<lang>` (english, japanese, korean, spanish, chinese-simplified, chinese-traditional, french, italian, czech, portuguese) |
| `--accept-seed-language <n>` | Consent to use seed n in a language other than English |

## `mr decode`

Print everything an mr1 card holds: the template, delta and anchors,
set id, card digest, the (0, 0) policy id, stub and md1 card (as md1
chunks when it is over 80 symbols), the seat map, the units, each slot
(its locks, what it removes and drops, whether it is open or a
lock-up), the set end, each slot's deadlines at epoch 0, and a bundle
checklist when the card lists other cards. It takes no keys.

### Synopsis

```sh
mr decode [OPTIONS] <mr1>...
```

### Flags

| Flag | Purpose |
|---|---|
| `<mr1>...` | The card's strings (one, or each chunk of a chunked card) |
| `--network <NETWORK>` | Network: main (default; `mainnet` is accepted too), signet, testnet or regtest [default: main] |

## `mr repair`

Correct up to 4 substituted characters per mr1 string. A chunk set is
repaired as one card, atomically: one uncorrectable string fails the
whole call with no output. A mixed-case string, and a string over 93
symbols after `mr1`, are refused before any correction. Exit `0`:
nothing to correct; `5`: corrected (a repair report and the corrected
strings on stdout); `2`: not correctable.

### Synopsis

```sh
mr repair [OPTIONS] <mr1 strings>...
```

### Flags

| Flag | Purpose |
|---|---|
| `<mr1 strings>...` | The strings to correct (one card: one string, or its chunk set) |
| `--network <NETWORK>` | Network: main (default; `mainnet` is accepted too), signet, testnet or regtest [default: main] |

## `mr member`

Print one member (e, s) of the set as split-chain descriptors, an md1
card or a BIP 388 wallet policy. It runs every hand-out guardrail
(open, clamped, reorder, lock-up and its window, deadline, horizon),
prints the slot's description, lock dates, costs and minimum deposit,
and warns when one key alone spends. With `--for-spend` it prints the
member as the source of a sweep instead: `importdescriptors` JSON on
stdout and the step-by-step Core recipe on stderr.

### Synopsis

```sh
mr member [OPTIONS] --epoch <E> --slot <S> --height <H> --time <T> <mr1>...
```

### Flags

| Flag | Purpose |
|---|---|
| `<mr1>...` | The card's strings (one, or each chunk of a chunked card) |
| `--epoch <E>` | The epoch E |
| `--network <NETWORK>` | Network: main (default; `mainnet` is accepted too), signet, testnet or regtest [default: main] |
| `--slot <S>` | The slot S |
| `--keys <mk1…\|records>...` | Keys: mk1 plates (a chunked plate's strings in one value, separated by spaces) or `[fingerprint/path]xpub` records, each optionally `@i=`-bound |
| `--keys-file <file>` | A file of keys: one `@i=<card>` per line, chunked cards as consecutive strings |
| `--seeds <seeds>...` | Seeds: ms1 plates or BIP-39 words, comma-separated, in order (seed 1 first) |
| `--seed-language <n>=<lang>` | The wordlist of seed n: `<n>=<lang>` (english, japanese, korean, spanish, chinese-simplified, chinese-traditional, french, italian, czech, portuguese) |
| `--accept-seed-language <n>` | Consent to use seed n in a language other than English |
| `--height <H>` | The tip's block height |
| `--time <T>` | The tip's median time past, unix seconds (any u32) |
| `--accept-tip` | Accept a tip whose height and time disagree with this release's anchor by more than 180 days |
| `--as <form>` | The output form Possible values: - descriptor: Split-chain, checksummed descriptors (receive, change) - md1: The member's md1 card (chunked if needed) - policy: A BIP 388 wallet policy for signer registration [default: descriptor] |
| `--open-slot` | Hand out an open member (some key spends sooner than the template allows) |
| `--accept-clamped` | Accept a lock clamped at its minimum by a shift, to-deadline or add-deadline (prints "spendable immediately by") |
| `--reorder-slot` | Accept a member whose paths open in another order than at slot 0 |
| `--lockup-slot` | Hand out a lock-up slot (no path spends without a lock) |
| `--lockup-no-window` | Accept a lock-up window shorter than --min-lead |
| `--accept-deadline` | Accept a deadline already past or closer than --min-lead |
| `--beyond-horizon` | Hand out a member beyond the heir's default scan |
| `--min-lead <L>` | The minimum lead, in days (default 30) [default: 30] |
| `--for-spend` | Print the member as the source of a spend: importdescriptors JSON (inactive, timestamp 0) on stdout, the spend recipe on stderr; skips the tip check, the deadline and horizon guardrails and the hand-out consents |
| `--accept-stub-mismatch` | Seat a plate whose policy-id stub is not this card's |
| `--accept-unconfirmed-seeds` | Use seeds nothing on the card confirms |
| `--min-deposit <sats>` | The minimum sensible deposit to print, in sat (replaces the reference figure) |
| `--compromised` | Declare this card's hot device lost or stolen (§7a): refuses unless --for-spend, which prints the destination rule |

`--as md1` prints the member's md1 card and a `md … --seat '@m=…'`
line per seated mk1 plate (with md's own `#k` ordinal where plates of
different cards share a chunk-set id); `--for-spend` refuses it. `--as policy`
sends a signer only a registrable policy, printing on stderr each
seat's xpub text and seat check and naming the seats filled only from
the card. On a card with a filled hot seat, a run without
`--compromised` ends with a one-line reminder to rerun with it if the
hot device was ever lost.

## `mr address`

Derive one address of a member, to check a receive or presigned-move
destination before using it. Every run prints "before the first
deposit to this set, check this address on a signer's screen". It
prints every hand-out refusal, the open one first; at a row other than
0 the open refusal names the slot-0 paths the row locks and the rows
that qualify instead. `--compromised` refuses at every row. An index
of 1000 or more warns: the heir's scan may not reach it.

### Synopsis

```sh
mr address [OPTIONS] --epoch <E> --slot <S> --index <I> --height <H> --time <T> <mr1>...
```

### Flags

| Flag | Purpose |
|---|---|
| `<mr1>...` | The card's strings (one, or each chunk of a chunked card) |
| `--epoch <E>` | The epoch E |
| `--network <NETWORK>` | Network: main (default; `mainnet` is accepted too), signet, testnet or regtest [default: main] |
| `--slot <S>` | The slot S |
| `--index <I>` | The address index I |
| `--keys <mk1…\|records>...` | Keys: mk1 plates (a chunked plate's strings in one value, separated by spaces) or `[fingerprint/path]xpub` records, each optionally `@i=`-bound |
| `--keys-file <file>` | A file of keys: one `@i=<card>` per line, chunked cards as consecutive strings |
| `--seeds <seeds>...` | Seeds: ms1 plates or BIP-39 words, comma-separated, in order (seed 1 first) |
| `--seed-language <n>=<lang>` | The wordlist of seed n: `<n>=<lang>` (english, japanese, korean, spanish, chinese-simplified, chinese-traditional, french, italian, czech, portuguese) |
| `--accept-seed-language <n>` | Consent to use seed n in a language other than English |
| `--height <H>` | The tip's block height |
| `--time <T>` | The tip's median time past, unix seconds (any u32) |
| `--accept-tip` | Accept a tip whose height and time disagree with this release's anchor by more than 180 days |
| `--change` | The change chain (/c+1/*) instead of the receive chain |
| `--open-slot` | Hand out an open member (some key spends sooner than the template allows) |
| `--accept-clamped` | Accept a lock clamped at its minimum by a shift, to-deadline or add-deadline (prints "spendable immediately by") |
| `--reorder-slot` | Accept a member whose paths open in another order than at slot 0 |
| `--lockup-slot` | Hand out a lock-up slot (no path spends without a lock) |
| `--lockup-no-window` | Accept a lock-up window shorter than --min-lead |
| `--accept-deadline` | Accept a deadline already past or closer than --min-lead |
| `--beyond-horizon` | Hand out a member beyond the heir's default scan |
| `--min-lead <L>` | The minimum lead, in days (default 30) [default: 30] |
| `--accept-stub-mismatch` | Seat a plate whose policy-id stub is not this card's |
| `--accept-unconfirmed-seeds` | Use seeds nothing on the card confirms |
| `--min-deposit <sats>` | The minimum sensible deposit to print, in sat (replaces the reference figure) |
| `--compromised` | Declare this card's hot device lost or stolen (§7a): refuses at every row |

**Presigned moves** stay broadcastable until their inputs are spent and
do not protect coins past the epoch deadline: migrate to a fresh epoch
before leaving, and on return treat the transaction as live until its
coins are moved. Their fee is fixed at signing, so they need a fee
ladder or a P2A anchor. (`mr address --help` prints this advisory.)

## `mr current`

Find the nearest epoch whose every absolute lock, in slot S (default
0), is at least a lead L away, each kind in its own units (a block
counts 9 minutes). Locks set by `open` are ignored; a slot with no
other absolute lock is measured by the card's deadline functions, and
the answer then changes only the branch. Without `--slot`, each
own-wallet row is answered too (`wallet at slot s: epoch E`).

It also prints, for each path of the answered member with a relative
lock, `path <keys> opens about N days after each deposit confirms`,
warning when that wait is shorter than your lead, and the migration
rule: every row's funds move to the same slot of the new epoch, and
only an open row's go to slot 0.

It refuses when no epoch meets the lead: `no epoch of slot S meets
lead L; a lead of at most <L′> still reaches epoch <E>` while one
still meets `--min-lead`, else `this slot ends at <date>; move to a new
set on new origin paths`. Past the heir's default scan it answers the
last epoch of the scan and prints the lead achieved (`lead 9.4 years:
the most the heir's default scan covers`), or refuses `this slot ends
within the heir's scan: move to a new set` when that lead is below
`--min-lead`. An epoch-less card answers epoch 0 for any lead. At a
tip past 2038-01-19 a slot whose member carries a time lock has no
epoch, and `current` answers only the other slots. It takes no
`--compromised` and prints no reminder.

### Synopsis

```sh
mr current [OPTIONS] --height <H> --time <T> --lead <L> <mr1>...
```

### Flags

| Flag | Purpose |
|---|---|
| `<mr1>...` | The card's strings (one, or each chunk of a chunked card) |
| `--height <H>` | The tip's block height |
| `--network <NETWORK>` | Network: main (default; `mainnet` is accepted too), signet, testnet or regtest [default: main] |
| `--time <T>` | The tip's median time past, unix seconds (any u32) |
| `--accept-tip` | Accept a tip whose height and time disagree with this release's anchor by more than 180 days |
| `--lead <L>` | The lead: how far every absolute lock must be from the tip (2y, 26w, 30d, 36h; a bare number is days; a block counts 9 minutes) |
| `--slot <S>` | The slot S (default 0; without it, each own-wallet row is answered too) |
| `--min-lead <L>` | The minimum lead: never offers a lead below it (default 30 days) [default: 30] |
| `--beyond-horizon` | Answer an epoch beyond the heir's default scan |

### Worked example

```sh
mr current mr1… --network testnet --height 1000000 --time 1900000000 --lead 5y
# tip = 1,000,000, ≈ 2030-03-17; this must be the current tip
# slot 0: epoch 1
# funds at slot 0 migrate to slot 0 of epoch 1; every row keeps its slot, …
```

### Synopsis

|---|---|

## `mr create`

Issue a new mr1 card from a template or preset: its keys, a slot table
and a tip. `create` runs every guardrail before it mints anything, and
refuses mainnet while the derivation path is provisional. It never
generates a seed: every seat's key comes from `--keys` (in the numbering
the template was typed in), except the hot seat's, which it derives from
the hot child.

### Synopsis

```sh
mr create [OPTIONS] [template]
```

### Flags

| Flag | Purpose |
|---|---|
| `[template]` | The template (BIP 388 form, `@j` placeholders in any order) |
| `--network <NETWORK>` | Network: main (default; `mainnet` is accepted too), signet, testnet or regtest [default: main] |
| `--template-preset <name>` | A template preset instead of a template: owner-heir, 2of3-heir, 3of5-2heirs, or any of them with `-tr` (taproot under `UNSPENDABLE(liana)`) |
| `--epochs` | Admit a delta that no slot uses (anchor-only epochs) |
| `--delta-blocks <N>` | The height delta Δ in blocks (a preset's default: 65,536) |
| `--delta-seconds <S>` | The time delta Δ in seconds |
| `--height <H>` | The tip's block height |
| `--time <T>` | The tip's median time past, unix seconds (any u32) |
| `--keys <mk1…\|records>...` | Keys: mk1 plates (a chunked plate's strings in one value, separated by spaces) or `[fingerprint/path]xpub` records, each optionally `@i=`-bound |
| `--keys-file <file>` | A file of keys: one `@i=<card>` per line, chunked cards as consecutive strings |
| `--round <r\|@j=r>` | Every seat's key round (`<r>`), or one seat's (`@j=<r>`, typed numbering); default 0 |
| `--sibling <mr1\|md1>` | An existing card of the owner's on these origin paths, or a hot-child history card (a chunked card's strings in one value, separated by spaces); repeat for each card |
| `--sibling-keys <keys>...` | The keys of the `--sibling` or `--bundle-card` before it (mk1 plates or records), for the collision test |
| `--no-other-cards-on-these-paths` | Attest that no other card of yours is on these origin paths |
| `--min-lead <L>` | The minimum lead, in days (default 30; 0 admitted) [default: 30] |
| `--accept-deadline` | Accept a deadline already past or closer than --min-lead |
| `--small-delta` | Accept a delta below 16,384 blocks or 9,830,400 s |
| `--accept-stub-mismatch` | Take a plate whose policy-id stub is not this card's |
| `--accept-tip` | Accept a tip whose height and time disagree with this release's anchor by more than 180 days |
| `--slots <file>` | The slot table as a rows file: one row per line, one operation per unit in `mr units` order |
| `--preset <none\|classic>` | The slot table as a preset: none or classic |
| `--anchor-height <A>` | The height anchor (a height delta with no template height after()) |
| `--anchor-time <A>` | The time anchor (a time delta with no template time after()) |
| `--seat-map <letters>` | One seed letter per stored seat, comma-separated (e.g. A,C,F) |
| `--word1 <@j=word>` | One seat's letter from its seed's first word (`@j=<word>`, typed numbering) |
| `--accept-typed-letter <@j>` | Admit a typed letter nothing confirms on a card without fingerprints (`@j`, typed numbering) |
| `--same-seed` | Accept two seats of the template filled by one seed |
| `--lockup-slot` | Accept a lock-up slot (no path spends without a lock) |
| `--lockup-no-window` | Accept a lock-up window shorter than --min-lead |
| `--reorder-slot` | Accept a row whose paths open in another order than at slot 0 |
| `--far-slot` | Accept a row whose path opens 5 years or more after slot 0's |
| `--open-slot` | Accept an open own-wallet row (sets its open-consent bit) |
| `--accept-set-end` | Accept a slot or time delta that ends before the tip plus the horizon |
| `--accept-anchor` | Accept an anchor before the tip or beyond the tip plus the horizon |
| `--own-wallet <s,…>` | Mark rows as their own wallets (slots, comma-separated) |
| `--role <name=role:seeds>` | A participant: `<name>=creator\|heir\|cosigner:<seeds>` or `<name>=helper`; one per participant |
| `--seeds <seeds>...` | Seeds: ms1 plates or BIP-39 words, comma-separated, in order (seed 1 first) |
| `--seed-language <n>=<lang>` | The wordlist of seed n: `<n>=<lang>` (english, japanese, korean, spanish, chinese-simplified, chinese-traditional, french, italian, czech, portuguese) |
| `--accept-seed-language <n>` | Consent to use seed n in a language other than English |
| `--passphrase <n>=<passphrase>` | A seed's BIP-39 passphrase, by input position (`<n>=…`) or by a letter one given seed has |
| `--accept-12-word <n>` | Accept 12-word seed n |
| `--no-fingerprints` | Leave out the Fingerprints TLV |
| `--horizon <years>` | The heir's default scan horizon in years (11 … 31; 10 is the default, written by omitting the field) |
| `--min-deposit <sats>` | The minimum sensible deposit to print, in sat |
| `--bundle-card <mr1\|md1>` | A bundle card (mr1 or md1): the list names it, and it is a sibling too; repeat for each |
| `--bundle-account <seed:purpose:n>` | A bundle account `<seed>:<purpose>:<n>` (a letter or `held`) |
| `--hot-child <letter:12\|24>` | Derive the hot child from the seed with this letter: `<letter>:<12\|24>` |
| `--hot <@j>` | The hot seat (`@j`, typed numbering): the hot child fills it |
| `--hot-on <set-id>` | Share the hot device with a given card (its set id or 32-bit prefix) |
| `--retire-child <letter/12\|24/i>` | A retired child of the parent: `<letter>/<12\|24>/<i>` |
| `--first-hot-child <letter>` | Attest that this is the parent's first hot child |
| `--compromised <set-id>` | Declare a given card compromised (its set id or 32-bit prefix) |
| `--hot-cold-seed` | Accept a seed on a short single-key path and in a quorum of one template |
| `--heir-holds-hot-path` | Admit an heir role listing `hot` whose slot-0 spend-today test fires only with the hot seat |

Mandatory: a template or `--template-preset`, the tip (`--height`,
`--time`; `mr` never reads the machine's clock), a key for every seat, a
slot table (`--slots` or `--preset`), a `--role` per participant, and the
sibling question: every existing card of yours on these origin paths as
`--sibling` (each followed by its `--sibling-keys` when needed), or
`--no-other-cards-on-these-paths`. `--sibling-keys` binds to the
`--sibling` or `--bundle-card` before it. Each of its keys goes only to
a seat of that card, at the key's origin path, that it is identified
with:

- `@i=<key>` binds seat i;
- an unbound key goes to the seat at its origin path whose Pubkeys TLV
  key it is; else to the one open seat there whose declared master
  fingerprint it carries; else, once those are placed, to the one open
  seat left there that it may be. An open seat has no key yet and no
  Pubkeys TLV key; a key may be an open seat's when that seat declares
  its fingerprint or none, or the key carries none (a declared or
  carried `00000000` counts as none);
- unbound keys that may each be several open seats' keys at their path
  fill, in any order, every open seat there that one of them may be,
  each key a seat of its own (the seats are then keyed, but none is
  identified; an open seat that none of them may be, since it declares
  another fingerprint, stays unknown). Fewer keys than those seats are
  refused as undecidable: give every key of that path, or bind each
  with `@i=`. Keys that cannot each take a seat of their own among those
  seats are refused: one of them is not that card's key;
- refused (exit 1): a key whose origin path is not its bound seat's, or
  no seat's; a seat the card lacks; a key whose master fingerprint is
  not the one the card declares for its seat, or none it declares for an
  open seat at its path (a key that carries no fingerprint, or
  `00000000`, is never refused for it, since it decides nothing); a key
  that contradicts the card's own Pubkeys TLV key for its seat; more
  keys at a path than the card has seats there; a key given twice for
  one card.

So on a card whose seats share a path (a BIP 48 multisig's
`m/48'/1'/0'/2'` for every seat), give every key of that path, in any
order, or bind each with `@i=`, unless the keys carry the fingerprints
the card declares. The collision test compares every key known for a
given card against every seat of the new card, whichever seat it went
to. It then tests every seat of the given card at a new seat's path by
master fingerprint, its key known or not, when both cards declare one
for it other than `00000000` (which counts as none, and two `00000000`
are not the same fingerprint): the same fingerprint collides, different
ones do not. A seat whose key is unknown and that no two fingerprints
decide is tested by its seed letter when both cards have seat maps (an
`mr1` card), else refused as undecidable. A collision names the seat the
key is identified with, or, for keys that filled a path's
undistinguished seats, those seats ("seat @0 or @1"). A seat's
identified key is a `--sibling-keys` key identified with it, else the
given card's own Pubkeys TLV key for it: an `mr1` card that carries its
keys needs no `--sibling-keys` for the checks below. The letter-reuse
warnings read a key only where it is identified with its seat, and a
declared `00000000` (on either card) as no fingerprint. The hot/cold
check across the given cards reads each seat's fingerprint, else its
identified key: a hot child that derives a cold seat's key is refused,
with no override, whether that key came from `--sibling-keys` or from
the card's Pubkeys TLV; a seed of the new card that derives a given
card's hot-seat key is refused the same way; and that key confirms the
card's hot parent, for the own-card question and `--hot-on`. A given
md1 is checked too, every one of its seats cold (it has no hot seat): a
hot child whose master fingerprint the md1's Fingerprints TLV declares
at a seat, or that derives a seat's key from `--sibling-keys` or from the
md1's Pubkeys TLV, is refused with no override ("hot child 24/0 of seed
A fills md1 1a2b3c4d's seat @2: …", the md1 named by its 8-digit id
prefix), and one that derives a key that filled a path's
undistinguished seats is refused on those seats, with no `--hot-on`
route; where nothing decides, nothing prints, since an md1 has no
letters. In `upgrade`, whose hot child is the md1's own, these
refusals end "`upgrade` keeps the md1's hot child, so this md1 cannot
be upgraded with that card beside it: move that card's funds and give
it up, or move this md1's funds with `create`, whose search takes
another child" in place of "let the search take another child". The
md1 that `upgrade` upgrades, given back, is set aside and not checked
(below: the same descriptor, every key identified with a seat equal to
that seat's key), or refused when nothing tells it from another
wallet's identical card (below); another wallet's md1 on the same template and paths,
its keys in other seats, is checked like any given card. A given md1 whose keys are
known (`--sibling-keys` or its Pubkeys TLV) is not listed as "the
cross-card hot/cold check was not possible". The hot/cold
check also reads keys that filled a path's undistinguished seats
of an `mr1` card: a hot child that derives one of them is refused on
those seats, or, when that card's hot seat is among them, refused as
undecidable (bind each with `@i=`) unless `--hot-on` names that card;
a seed of the new card that may be that card's hot child the same way
is refused as undecidable; and such keys do not confirm the card's hot
parent (the own-card question's "no" and `--hot-on` say to bind each
with `@i=`).

`create` prints the template in the stored numbering, the epoch axis, the
table and each row's meaning, the scan sizes, the set id and card digest,
the role table (each seat's typed `@j` beside its stored `@i`), the card,
the (0, 0) stub and md1 card, the bundle list, every kit with its notes,
the `mk encode` command for each extra plate, the spending cost, the
signer notes and, last, a closing checklist (the `mr verify` steps, the
signer check, the Jade registration cap, migrate on spend). A print that
names a seat carries the typed `@j` beside the stored `@i` when they
differ. Seed words, a seed's word 1 and the hot child's words go to
stderr only; passphrases are never printed, and a passphrase typed at
the prompt is read with the terminal's echo off (where the terminal
cannot turn it off, as in mintty, a warning says so before the
question). A refusal comes before any of this is printed.

Every message `mr` writes, in every verb (a refusal, a warning, clap's
own usage error, a template's parse error), quotes a value you typed only
when that value parsed as a public typed value: an `mr1`, md1 or mk1 card
string, an `xpub`/`tpub`, an 8-hex-digit fingerprint, a 16-hex-digit set id or
card digest, an `export --next` digest prefix (8 to 16 hex digits), a
derivation path (at most 255 components) or a number that fits its flag
(at most 20 digits); a verb, a flag name, a row operation, a
language name or one of a flag's listed values; a `--role` name or hot
device name that `create` took; or a template, printed from its parsed
form. Anything else is named by its flag and position, never quoted:
`` `--role` value 2: unknown role (creator, heir, cosigner or helper) ``,
`` `--slots` line 3: operation 2 is not a row operation ``, `invalid
value for '--min-lead <L>' at position 5 (not echoed): …`, `unexpected
argument at position 21 (not echoed)`. A line that says "not echoed"
never holds the value: a number out of a flag's range is refused with
the range only (`not in 0 … 4,294,967,295`), however it was typed (a
leading `+` or zeros included). Every typed value that is
quoted has a bounded shape, so a secret pasted into its slot is never
quoted back: a digest prefix longer than 16 digits (a card digest has
16) is a usage error (exit 2), and a longer number is named by its
count of digits. A file is named by its flag, not
its path (`` `--slots`: cannot read the file ``, `` heir file written
(the `--heir-file` path) ``). A template's parse error names the bad part by its
character (`template: at character 17: …`) and keeps the parser's own
words only when none of them comes from the template; a value with no
`(` is named by what it looks like (`seed words (24 words, not
echoed)`, `an extended private key`, `a bare word`). The report itself
(cards, descriptors, digests, the plan) is printed as it is. What is
shown on purpose, the only exceptions: the seed words and word 1 that
`create` and the read verbs print on stderr, the hot child's words, the
nearest list words a `--word1` refusal suggests, and the `--role` and
device names `create` took. `repair` prints the characters it corrected
(`'was' -> 'now'`), as the spec requires. A `--role` name and a hot
device's name are printed on the kits, so `create` bounds them: a name
may hold at most 5 words and 40 characters, and no word longer than 12
characters. Its words are the pieces between spaces, `-`, `_`, `.`,
apostrophes or any other punctuation (`bank-box-7` is 3, `Alice's
phone` is 3), with words of a BIP-39 list run together counted one by
one, past any stray character among them (`camp1calm` is 2), and each
Chinese character counted one. A longer name is refused, never echoed:
`` `--role` value 1: the name is too long (not echoed): a name may hold
at most 5 words and 40 characters, and no word longer than 12
characters; … ``. So `alice`, `home-safe`, `aunt-mary`, `ledger nano`,
`Alice's phone`, `Ledger Nano S Plus`, `Papa's Trezor Model T`, `李明`
or `张伟的手机` are fine, and `the blue ledger nano in the fire safe at
the lake house` is refused, as is a single word of more than 12 letters
(write it in two, with a separator): keep a name short.
A name that is key-shaped is refused by its kind whatever its length:
an extended private key, a WIF, an ms1 string or hex of 32 digits or
more (with `0x` or in groups). A `--role` name is checked before
`create` asks anything on stdin; the device's name is the last question
and is checked as soon as it is read, so a refused device name means
answering the questions again. The bound is about a name's size, not a
promise about every secret: a name it takes shows at most 5 words of a
phrase as typed, each a whole list word or a Latin list's 4-letter
prefix, glued or not; a stray or mistyped character in a glued run
hides none of the run's other words, which are counted past it. What
the bound does not count are words typed with a mistake or cut short below 4 letters (not list
words): glued into tokens of at most 12 characters, a label of 40
characters can hold 12 3-letter words each with one letter wrong or cut to their first 3 letters. A
name taken is printed on the kits and in a refusal that names the
participant (`role carol=helper lists seeds`). The command line itself
(shell history, the process list) is outside `mr`'s reach.

With `--hot-child <L>:<12|24>` it derives a BIP-85 child of seed L (given
in `--seeds`) as a cheap hot wallet, and with `--hot @j` that child fills
the hot seat too. A hot-child run needs a history input for seed L: your
newest card with a child of L (`--sibling` or `--bundle-card`),
`--retire-child`, or, only for L's first hot child, `--first-hot-child L`.
It asks on stdin, after the template's own refusals (the guardrails and
the spending cost), in this order: a no-seat parent's passphrase a second
time (when the parent fills no seat and has one), `is set <id> your own
card …?` for each given card whose parent it cannot confirm (answer
`yes` or `no`), and the name of the device that will hold the child (a
free label). With no answer to the passphrase or the device name it
refuses; no answer to the own-card question counts as no. It prints the
reservation of indexes 0 … 15 before the child's words, the child's path
and index, the cheap hot wallet's descriptor and first addresses (BIP 86,
84, 49 and 44), and puts the hot device check in the closing checklist.

## `mr upgrade`

Issue an mr1 card whose member (0, 0) is the wallet of an existing md1
card, so the wallet you already funded becomes the card's first member.
`upgrade` is `create` over the md1 card's descriptor, in the md1's own
numbering (`@i` is the md1's `@i`): the template, the origin paths and
the path convention's rounds are the md1's, and every other rule,
guardrail and print is `create`'s. It refuses mainnet while the
derivation path is provisional, and never generates a seed.

### Synopsis

```sh
mr upgrade [OPTIONS] <md1 card>...
```

(`--slots` or `--preset`), a `--role` per participant, the sibling
question (`--sibling …` or `--no-other-cards-on-these-paths`), and a key
for every seat the md1 carries no xpub for, as `--keys @i=<key>` in the
md1's numbering. A seat the md1 keys takes the md1's xpub; a key given
for it must be the same. `upgrade` has no `<template>`,
`--template-preset`, `--round` or `--min-deposit`.

**The witness.** An md1 with any seat it does not key needs a witness of
the funded seating: `--witness-md1` (a keyed md1 of the wallet),
`--witness-descriptor` (either chain, or the `<0;1>` pair) or
`--funded-address <addr> --index I [--change]`. The keys, the hot
child's included, are seated by §4's seating rule as the heir runs it
on the new card, with the fingerprints the card carries; a key the rule
would seat elsewhere is refused ("an heir would seat it wrong"). That
happens only on a card without fingerprints, where two seats at one
origin path are seated by canonical order: the refusal tells you to drop
`--no-fingerprints`, so each plate is seated by its fingerprint, or to
`create` a card on a new account. The witness must show member (0, 0)
under that seating; otherwise `upgrade` refuses, since the wallet was
funded under another seating ("the fix is a new md1 card or `create` on
a new account"). A witness is named by its flag in a refusal, never
quoted. A fully keyed md1 needs none: `upgrade` derives its own
addresses.

**What it checks and prints**, before the card: every refusal of the md1
and its witness comes before any line (an `mr1` given as the md1, a hash
fragment, a repeated placeholder, an origin that is unspecified,
`--no-fingerprints` on an md1 that carries fingerprints). Then, after
the "(0, 0) md1 card:" block: "(0, 0) check: member (0, 0) decodes to
the md1 card's descriptor, template id X"; the policy id, unchanged or
changed only by the Fingerprints TLV `upgrade` adds (then it also tells
you to re-mint every mk1 plate with its origin fingerprint); the witness
line; whether the card's payload P equals the md1's bits, and why not;
the seats told apart only by fingerprint; and (0, 0)'s deadlines with
dates. When a (0, 0) deadline is past, or less than `--min-lead` after
the tip, it says every coin at (0, 0) is spendable by the heir path (now,
or from a date) and prints the three commands of the §7a sweep
(`current`, `address`, `member --for-spend --as descriptor`), each with
the new card's strings, `--network` off mainnet and the `--height` and
`--time` you gave; you fill in the receiving epoch `E` and the index
`I`, and the keys `<mk1…>` when the card has a seat it does not key. A
height deadline at the tip counts as past, since the heir path spends
in the next block; a time deadline counts as past only before the tip's
time. The card is issued all the same. An heir whose kit spends (0, 0)
today, when the first receivable epoch is later, is warned, not
refused.

**Hot child.** The hot flags work as in `create`. The hot seat's key
must be the md1's: when the md1 keys the hot seat, or declares its
master fingerprint, the child the search takes must match, or `upgrade`
refuses (`` `@i`, the hot seat: … `upgrade` keeps the md1's keys ``;
check `--hot-child`, the history inputs and the parent's passphrase).
An heir listing `hot` is rerun at epoch 0 as well as at the first
receivable epoch, and needs `--heir-holds-hot-path` wherever the hot
seat makes their kit spend today. `--hot-child L` is refused when two
seats of letter L carry different fingerprints, or a role lists `L#…`.
`--hot-on` beside a given card of a newer child of the parent, or of
the other length at the same index, is refused as in `create`, but the
refusal ends "`upgrade` keeps the md1's hot child, so this md1 cannot
be upgraded on that device: move its funds with `create`, whose search
takes a new child" in place of "let the search take a new child".

`upgrade` admits two seeds that share a letter (seated by the Fingerprints
TLV, so `--no-fingerprints` is refused for them); a role then names each
as `<letter>#<fingerprint>`. The md1 given back, as `--sibling` or
`--bundle-card`, is set aside with a note and is neither listed nor
counted in the bundle list. The note says it is the card being upgraded
when every seat's key is known (from its keys or `--sibling-keys`) and
equal to the seat's, with no fingerprint that differs: the keyed md1
itself, or a keyed copy of it (the same template and origin paths). A
key identified with a seat (bound with `@i=`, the card's own Pubkeys
TLV key, or placed by the fingerprint the card declares for that seat)
must be that seat's key: a mirror wallet, whose card keys the heir's
key at @0 and the hot child at @1 where the md1 has them the other way
round, is another wallet and is refused as one key on two cards. Only
keys given unbound at a path several seats share, whose seat nothing
tells, are compared as a set, in any order, and only on a card with
the md1's own payload: a card of another payload (no Fingerprints TLV
where the md1 has one, say) with such keys is tested as a sibling;
bind its keys with `@i=` to have them compared seat by seat. Even on
the md1's own payload, such keys are trusted only where the
fingerprints the card declares tell those seats apart (each seat
declares one, all different). An md1 without fingerprints, given back
with its keys unbound at a path two or more seats share, is byte for
byte another wallet's card with those keys in other seats (a mirror
wallet whose cold seat holds the hot child, or two cold seats
swapped), so it is refused, with no override: "`--sibling` md1
1a2b3c4d has the payload of the md1 being upgraded, but its
`--sibling-keys` fill its seats @0 or @1 at m/48'/1'/0'/2' unbound, so
nothing tells it from another wallet with those keys in other seats:
bind each with `@i=`, or leave the card out". Bound with `@i=` to its
own seats, it is set aside; left out, the run is the same. An
md1 with the md1's own payload and a seat whose key is unknown is set
aside too, when no key you give for it with `--sibling-keys` differs
from the seat's (at a shared path, when each is one of that path's
seats' keys, placed as above; a partial set of unbound keys that
nothing places is refused, as for any card); its note says only that it has the same
payload as the md1 being upgraded, since another keyless wallet on the same template
and paths, without fingerprints, has that payload too. Any other given
md1 is tested as a sibling, even one with the same payload: a key that
differs makes it another wallet (kept in the bundle list as a bundle
card), a shared key is refused as one key on two cards, and a seat that
cannot be decided asks for `--sibling-keys`. Each kit's notes
give each seat's origin path as the card has it: the md1's own path
(such as `m/48'/1'/0'/2'`), or the path convention's when the md1's
paths are the convention written out.

## `mr export`

Export watch-only descriptors for a wallet or an heir: every member of
the chosen epochs and slots, each labelled with (e, s) and its unlock
heights or dates, as ready `bitcoin-cli scantxoutset` calls in windows of
1000 indexes (main calls over indexes k·1000 … k·1000 + 999, probe calls
over the top 100), batched at 1,000,000 scripts per call. The output
begins with each card's bundle list as a checklist. With `--seeds` it
also derives the bundle list's accounts (the cheap hot wallet included,
with its first address and restore text) and, unless
`--no-child-discovery`, the child discovery accounts. It never refuses
over a tip: the tip check is a warning.

### Synopsis

```sh
mr export [OPTIONS] <mr1>...
```

### Flags

| Flag | Purpose |
|---|---|
| `<mr1>...` | The card's strings (one, or each chunk of a chunked card) |
| `--card <mr1>` | Another card of the bundle, scanned with the same keys or seeds (a chunked card's strings in one value, separated by spaces); repeat for each card |
| `--network <NETWORK>` | Network: main (default; `mainnet` is accepted too), signet, testnet or regtest [default: main] |
| `--keys <mk1…\|records>...` | Keys: mk1 plates (a chunked plate's strings in one value, separated by spaces) or `[fingerprint/path]xpub` records, each optionally `@i=`-bound |
| `--keys-file <file>` | A file of keys: one `@i=<card>` per line, chunked cards as consecutive strings |
| `--seeds <seeds>...` | Seeds: ms1 plates or BIP-39 words, comma-separated, in order (seed 1 first) |
| `--seed-language <n>=<lang>` | The wordlist of seed n: `<n>=<lang>` (english, japanese, korean, spanish, chinese-simplified, chinese-traditional, french, italian, czech, portuguese) |
| `--accept-seed-language <n>` | Consent to use seed n in a language other than English |
| `--height <H>` | The tip's block height (with --time): the default scan, epochs 0 … e_hi |
| `--time <T>` | The tip's median time past, unix seconds (with --height) |
| `--horizon <D>` | The horizon in years (default: the card's horizon field, else 10) |
| `--epochs <a..b>` | Scan epochs a … b (inclusive) instead of the default range |
| `--exhaustive` | Scan every valid epoch |
| `--next <k[:target]>` | Emit window k of the run (k ≥ 1, or 0 with a target; at most 2,147,482), optionally narrowed to targets, repeated with one k: `[<digest prefix>:]<e>/<s>` (the prefix 8 to 16 lower-case hex digits), or a bundle entry (`held:84:0`, `C:84:0`, `A/24/0:86:0`) |
| `--history` | Check history, spent or not: the gap-20 address-index output and the Core rescan, instead of the quick scan |
| `--child <n>=<letter>/<12\|24>/<i>` | Declare given seed n to be the child `<letter>/<len>/<i>` a bundle entry names (e.g. `2=A/24/0`), as a `hot` kit's child plate reads |
| `--try-seatings [<K>]` | Export every seating of the undecided seats, up to K! of them (default K = 4, i.e. 24) |
| `--heir-file <file>` | Also write window 0's calls, headed by the set id, card digest, tip, horizon and epoch range, to this file: a fallback that needs no `mr` (it holds every descriptor, so every address) |
| `--no-child-discovery` | Leave out the child discovery scan (account 0 of each given seed's BIP-85 children 0 … 15, both lengths, four purposes) |

A card with an epoch axis needs one of the tip (`--height`, `--time`),
`--epochs a..b` or `--exhaustive`; an epoch-less card defaults to
`--epochs 0..0` and refuses any other range. Beside every probe call
`export` prints the ready `mr export <the same arguments> --next <k + 1>`
command: run it while a probe call finds any unspent output. Each card
prints the rule's `@i=` binding list after its set id and a seating
count with its scan time; seatings the card cannot decide (seats at one
origin path with nothing to tell their plates apart) are exported only
with `--try-seatings`, each labelled with its binding list and a ready
`member --for-spend` stem, and a count above K! is refused with its scan
time. `--next` may be repeated with one k, each value naming a target
(`--next 1:0/0 --next 1:held:84:0`): the run emits the union of the
targets' descriptors; two different k are refused. `--history` leaves
the child discovery accounts out; a discovery account prints its own
`--history --next 0:<entry>` command, and `--history`'s ready
next-window command keeps the run's targets. A seventeenth seed is
refused: run `export` once per group of at most 16 seeds.
`--heir-file` warns on stderr that the file holds every address of the
set. The file covers the whole run, so it is refused with a `--next`
target; with `--history` it holds window 0's main and probe calls and
then both history outputs.

### Worked example

```sh
mr export mr1… --network testnet --keys mk1… mk1… --height 1000000 --time 1900000000
# card 1: set id 0bcbf7c84ecc9a8b, card digest 01a0adbdf3d19c6e
# rule: @0=plate 1, @1=plate 2
# epochs 0 … 7 (the default scan: e_hi at this tip and horizon); …
# main call 1 of 1: 16 descriptors, 16,000 scripts, about 33 s
# bitcoin-cli scantxoutset start '[{"desc": …, "range": [0, 999]}, …]'
# if any unspent output: mr export <the same arguments> --next 1
```
