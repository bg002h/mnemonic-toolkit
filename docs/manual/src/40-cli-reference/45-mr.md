# `mr` (mr-cli) reference

The standalone CLI for the Refugium mr1 format (mnemonic-refugium /
mr-codec). An mr1 card describes a whole set of wallets: one template
(a BIP-388 wallet policy), an epoch axis that moves its deadlines
forward, and a table of slots (rows) that change the template per
wallet. Each wallet of the set is a *member* (e, s): epoch e, slot s.
The card also carries the (0, 0) member as an md1 card.

This chapter mirrors mnemonic-refugium's `mr-cli`: the writers
`create` and `upgrade`, and the read-side verbs `verify`, `decode`,
`repair`, `member`, `address`, `current`, `units` and the heir's
`export`.

:::primer
A *slot* is a row of the card's slot table: slot 0 is the template as
written, and each further slot changes some of its units (switches a
branch off, shifts a deadline, adds a wait). An *epoch* moves every
deadline of the template forward by the card's delta, so the same slot
at a later epoch is a new wallet with later deadlines. `current` tells
you which epoch to use now; `member` and `address` hand out that member.
:::

Every subcommand below accepts `--help` (`-h`) for inline help. Each Flags table quotes `mr <verb> --help` verbatim.

## Conventions

| Topic | Rule |
|---|---|
| Card input | The positional `<mr1>...` is one card: a single `mr1` string, or every string of a chunk set, in order. A chunk set is always one card, never several. It may come before or after the options: `--keys`, `--seeds`, `upgrade`'s `--sibling-keys` and `export`'s `--try-seatings` take every value up to the next flag, but an `mr1` string among their values (no key or seed starts `mr1`) is read as the card, in the order typed, also after two such flags in a row, so `mr verify --network testnet --keys mk1… mk1… mr1…` and `mr verify --network testnet --seeds ms1… --keys mk1… mr1…` work; `upgrade` reads an `md1` string there as its card the same way, and refuses an `mr1` string typed there as ``an md1 card argument is an mr1 string`` |
| Checksums | Every reading verb **verifies only**: a string that is not a valid codeword is refused (`the mr1 checksum does not verify`), never corrected silently. Correction is `mr repair`'s job. The same holds for each string of an mk1 plate given with `--keys`, `--keys-file` or `--sibling-keys`, in every verb that reads one: a string that needs a correction is refused, ``key <k>, string <j> of <n>: the mk1 checksum does not verify: a character was typed or engraved wrong (`mk repair` corrects up to 4 substituted characters and names them); check what you typed against the plate, then type it again, or re-engrave the plate if the plate itself is wrong``, and one beyond correction ``… does not verify and cannot be corrected: more than 4 substitutions, or a character left out or added (which `mk repair` does not correct): count its characters and check each against the plate; …`` |
| Network | `--network <NETWORK>` is global: `main` (the default; `mainnet` is accepted as an alias), `signet`, `testnet` or `regtest`. It picks the address format, `xpub` or `tpub`, the tip anchor and the coin type. Any other value is a usage error. A card on the path convention does not record its network, and this release issues no mainnet card (the Refugium purpose number is provisional), so `decode`, `verify`, `member`, `address`, `current` and `export` refuse every card when `--network` is not given, a path-convention card and one with explicit origin paths alike (exit 1: ``no --network given, and this release issues no mainnet card … rerun with `--network signet`, `--network testnet` or `--network regtest` (or `--network main` to read it as mainnet)``); `--network main` given reads it as mainnet. A card with explicit origin paths (an upgraded md1's) may record a coin type there (each path's second step `0'` or `1'`); read on a given `--network` of the other coin type, it is read on that network all the same, with a warning: ``warning: this card's origin paths carry coin type 1' (signet, testnet and regtest), but --network is main: the card is read on main, as given; if the wallet is on signet, testnet or regtest, rerun with …``. Such a step need not be a coin type (Core's `m/0'/0'/k'`), and read-side verbs work on any network; `upgrade` warns the same way when the md1's paths carry the other coin type, so a mainnet-path md1 upgraded on signet reads back on signet. A plate at a seat's path under the other coin type is set aside naming the network (``plate at m/499'/1'/0': no seat of this card with `--network main`; it is seat @0's path on a test network: rerun with …``), and a seat left empty by it is refused the same way (`seat 0, letter A: no seed and no plate given; plate 1 at … is this seat's path on a test network: rerun with …`). `units` reads a card on any network |
| Tip | The tool never reads the machine's clock. Every verb that measures a deadline takes the chain tip as `--height H --time T` (the median time past, unix seconds; `--time` takes any u32) and prints `tip = <height>, ≈ <date>; this must be the current tip` first. On mainnet a tip whose height and time disagree with the release's anchor by more than 180 days is refused unless `--accept-tip`; off mainnet it only warns. On testnet (testnet3, whose min-difficulty blocks decouple height from time, and whose anchor is its genesis block) the check gives one line in place of that text, ``warning: test chains do not keep 10-minute blocks: the tip check and the dates are rough; check the tip by hand``, with no release advice and no `--accept-tip`. The line is printed on every run on a real testnet3 tip, since the anchor is the 2011 genesis block and a current tip is always years off it (only a tip within 180 days of the genesis block, which no card minted by this release can carry, draws nothing more than the tip line); `--accept-tip` is accepted there and changes nothing, because the check never refuses off mainnet and there is nothing to override. Signet keeps the check: its signed blocks are targeted at 10 minutes and the §7a rehearsal is built on its anchor, but whether a live signet tip stays within 180 days of that extrapolation was not checked against a node, so a signet tip may draw the mainnet text. When the tip's time is before the anchor's the second line reads ``the tip's time is N days before this release's anchor (2024-04-20): check `--time` `` in place of the anchor's age. On every network a tip no chain can have is refused, with no override: a height of 500,000,000 or more (`tip height … is not a block height: …`; from 500,000,000 an nLockTime is a unix time) or a time before the network's genesis block (`tip time … is before this network's genesis block …`), each naming `--height` and `--time`, since a swapped pair gives one; `export` only warns, and dates no height from such a tip (`warning: heights are printed without dates: this tip is not one a chain can have, so no date is estimated from it`). `member --for-spend` runs no tip check, so recovery is never blocked by it: it prints only the tip line. `export` has no `--accept-tip`, so its warning leaves out the advice to pass it |
| Numbers | Printed numbers carry thousands separators (`1,260,000`), except in script text, command lines, flag values, indexes, epochs and hex ids |
| Streams | Results go to stdout; warnings go to stderr as `warning: …`; errors print as `mr: <message>`. A reader that closes the pipe early (`mr decode --network testnet … \| head -1`) only stops the output: the exit code is the verb's own. Any other write error on stdout (a full disk, `> /dev/full`), from a verb or `--help`, prints `mr: cannot write the output: <error>` and exits 1. A stdout closed outright (`>&-`) behaves as `> /dev/null`: the output is discarded and the exit code is the verb's own |
| Secrets | `mr` never prints a private key, entropy or an ms1 seed string. It prints seed words in one case only: for each seed that `--seeds` gives as BIP-39 words, stderr carries `seed <n> read as <language>: <words>` once, so the words can be checked against the backup. Treat stderr as secret whenever `--seeds` holds words. A card argument that does not start `mr1` is never echoed: seed words (spaced or comma-joined), an ms1 string, an mk1 string or an md1 string is refused by every verb but `units`, which reads an md1 card (below), naming only what it looks like, e.g. `a card argument looks like seed words (<n> words, not echoed): seeds go in --seeds, and a card is its mr1 strings`. `member`, `address` and `current` refuse any other non-`mr1` value the same way, quoting only a bare integer of at most 20 digits (the `--epoch`/`--slot` hint); `units` reads a non-`mr1` argument as a template: one with no `(` is never a template and is never quoted, only named by its kind (an extended private key, a WIF or base58 key, hex, seed words joined by any punctuation, or a bare word), and a template's parse error names a bad part by its character, never quoting it. A usage error never echoes a value at all (a phrase typed without its verb, as a flag's value, or as the `<lang>` of `--seed-language 1=<lang>`): it names the value by its position, and keeps the verb and flag names as they are. The command line itself (shell history, the process list) is outside `mr`'s reach |

### Exit codes

| Code | Meaning |
|---|---|
| `0` | success |
| `1` | refused or failed (a guardrail, a check, a key that does not fit; also a mandatory input `mr` checks itself and finds missing: `--delta-blocks`/`--delta-seconds`, `--anchor-height`/`--anchor-time`, a participant's `--role`, a `--sibling` answer, `--slots` or `--preset`; the spec's list of usage errors is closed, and only the tip was added to it) |
| `2` | usage error (unknown flag, bad value, a missing argument the parser requires, a missing tip in `create`, `upgrade`, `member`, `address` or `current`); `mr repair`: nothing could be corrected |
| `5` | `mr repair` only: the strings were corrected |

### Keys and seeds

`verify`, `member` and `address` take the set's keys in one of these
forms. On a card whose Pubkeys TLV keys every seat, `member`, `address`
and `export` need neither `--keys` nor `--seeds`: every key comes from
the card (`member --as policy` still needs a seed or plate for a seat,
since a signer registers only a key it holds). On a card with a seat it
does not key, `member` or `address` given neither is a usage error
(exit 2), and `export` refuses it (exit 1).

| Form | Meaning |
|---|---|
| `--keys <mk1…>` | an mk1 plate (a chunked plate's strings in one value, separated by spaces) |
| `--keys "[fp/path]xpub"` | a record: a key in `verify`; double-quote it (or write the path's `'` as `h`, still quoted in zsh, whose `[…]` is a glob): an unquoted `'` opens a shell quote in bash, zsh, sh and fish, so two records merge and lose their `'`s, which `mr` refuses with ``…; if a shell merged records, quote each record, or write the path with h: …``; the record's xpub must be at its path, its depth the path's length and its child number the path's last step (as `mk encode` requires), in every verb that reads one: ``key <k>: the record's xpub is at depth 3, child 0', not at m/499'/1'/1' (depth 3, child 1'): the device exported another path; export the key at m/499'/1'/1'``, so a record whose `'`s a shell stripped (an even number typed unquoted) is refused the same way, with the shell hint; a key as `mr` prints a seat no seed or plate gave (`member --as policy`'s foreign key, depth 0 with no parent) is no device's export and is refused naming that: ``key <k>: the record's xpub is at depth 0 with no parent, not at <path>: a key as `mr` prints a seat no seed or plate gave (a foreign key, spec §7 `member`), not a device's export; give the key its device exports at <path>, or its plate``; a record whose xpub does sit at a path with no hardened step is read and warned of (every Refugium path `m/Pr'/coin'/(32·r + i)'` is hardened): ``warning: `--keys` value 1: key 1: the record's path has no hardened step, … if a shell stripped its `'`s, quote each record, or write the path with h: …``; a record that does not parse is refused naming the fault, never quoting it: ``…: the xpub is followed by a derivation suffix (such as `/<0;1>/*` or `/0/*`): give the account key alone``, ``…: the path begins with `m/` inside the brackets: write the steps alone, `[fingerprint/84h/0h/0h]```; in `member` and `address` it only confirms a seat that a seed supplies; `member --for-spend` refuses one |
| `--keys "@i=<key>"` | the key bound to seat `@i`, in the card's stored numbering (double-quoted, as a record above) |
| `--keys-file <file>` | one key per line (`@i=<card>` or the key alone), a chunked plate's strings on consecutive lines; blank lines and `#` comments are skipped; a plate ends at its chunk count, and a plate's first string always starts a new one, so a string that does not verify is named within its own plate (`key <k>, string <j> of <n>`), its chunk header read as typed when the string is beyond correction (unless a header character itself is wrong, a plate whose every string is beyond correction no longer draws in the next plate's) |
| `--seeds <seeds>` | ms1 plates or BIP-39 words, seed 1 first: a seed's words separated by spaces, seeds separated by commas (12 or more one-word seeds in a row, each a BIP-39 list word, are refused as one seed's words joined by commas: ``seeds <a> to <b> are one word each, every one a BIP-39 list word: these look like one seed's words joined by commas; separate a seed's words with spaces, and seeds with commas``). An ms1 plate may be typed as engraved: its groups separated by spaces or hyphens (`ms encode`'s engraving card), or by commas (`--separator comma`: each piece after an ms1 piece that is a run of bech32 characters with no space is read as one of its groups, until the pieces spell the next plate's `ms1`), at any group size, 1 and 2 included, all lower or all upper case (BIP 93: a plate that mixes them is refused ``seed N: the plate mixes upper and lower case …``); a refusal never quotes it; a plate whose checksum fails is refused ``seed N: the ms1 plate does not verify: check it character by character against its engraving; `ms repair` corrects substitutions`` |

A seed of one of this card's seat letters must fill a seat or agree with
the plate, record or card key that fills it. It is checked against that
seat's plate or record even when a plate fills the seat, unless its master
fingerprint is another seat's, so a wrong seed or a wrong passphrase is
never passed in silence. `verify`, `member` and `address` refuse (exit 1):

- a seed that gives a filled seat another key: ``seat <i>: seed <n> and
  plate <k> give different keys: a wrong plate, a wrong seed or a wrong
  passphrase; drop one or fix it (`verify`, `member` and `address` take
  no passphrase yet: if seed <n> has one, leave it out, and plate <k>
  fills the seat)`` (`record <k>` and `a wrong record` when a device
  record fills the seat);
- a seed of a seat's letter that derives no seat's key: ``seed <n> (letter
  <L>, fp <fp>) derives no seat's key: a wrong seed, a wrong passphrase,
  or another card's seed of letter <L>? drop it or fix it, and verify each
  card with the seeds of its own seats (`verify`, `member` and `address`
  take no passphrase yet: if seed <n> has one, leave it out and give its
  seat's mk1 plate with `--keys`)``;
- on a card with fingerprints, a seat whose fingerprint no given seed has
  while a seed of its letter was given (a wrong seed, or the seat's seed
  without its passphrase): ``seat <i>, letter <L>: no given seed has its
  fingerprint; seed <n> has this letter but fp <fp>, not the card's <fp>:
  a wrong seed or a wrong passphrase? (`verify`, `member` and `address`
  take no passphrase yet: if seed <n> has one, leave it out and give seat
  <i>'s mk1 plate with `--keys`)``. The seed named is one of the seat's
  letter shown to fill no seat: no seat declares its fingerprint, its key
  is not a seat's (the card's xpub, a given plate or record, or the key
  the run already seated), it is not the hot child's parent (its child's
  fingerprint or key is the hot seat's, or the card gives nothing to
  check the child against) and the run has not already seated it. So a
  seed that fills another seat, the hot seat's parent included, is never
  named. When there is no such seed, or the card declares no fingerprint
  for the seat, the text ends at ``… has its fingerprint``;
- a seed of the hot entry's parent letter whose child is not the hot
  seat's (a wrong parent, or the right one without its passphrase):
  ``seed <n> (letter <L>, fp <fp>) has the hot entry's parent letter, but
  its child <len>/<i> gives no seat's key: a wrong parent, a wrong
  passphrase, or another card's seed of letter <L>? drop it or fix it, and
  verify each card with the seeds of its own seats (`verify`, `member` and
  `address` take no passphrase yet: if seed <n> has one, leave it out and
  give the hot child's own words in its place)``;
- a seed with a seat's fingerprint and another letter, a seat the card
  keys included: `card letter <M> for seat <i> is wrong: seed <n>, letter
  <I>, has its fingerprint; re-engrave the card before any deposit` (in
  `member` and `address`: `card letter <M> for seat <i>, seed <n> has
  letter <I> and this seat's fingerprint: the card's seat map is wrong
  for this seat; re-engrave the card before any deposit`);
- a seed that derives a seat the card gives another letter: `seed <n>
  (letter <L>, fp <fp>) derives seat <i>'s key, but the card gives seat
  <i> letter <M>: the card's seat map is wrong for this seat; re-engrave
  the card before any deposit`.

The hot parent warning ("seed <n> has letter <L> but its child … is not
this card's parent, or its passphrase is wrong") accompanies the refusal
about the hot parent (and the run in which no seed fills a seat); a
refusal about another cause (a seat missing, say) does not carry it, since
there it could name a seed that is the card's own right seed.

Another card's seed looks exactly like a wrong seed when it shares a
letter with one of this card's seats or with the hot entry's parent, so
those runs are refused as above: verify each card with the seeds of its
own seats.

On a card with fingerprints, `export` still tries a seed of a seat's
letter whose fingerprint no seat declares there, as a labelled candidate
(a recovery never blocks on a fingerprint): its warning adds ``seed <n>
has fp <fp>, not the card's <fp>: a wrong seed or a wrong passphrase?
(`export` takes no passphrase)``, and the candidate's descriptor shows
the candidate's own fingerprint, never the card's. The seat is marked
on stdout and in the heir file too, one line per such seat: ``candidate:
seat @2, letter C: seed 1 (fp 7698a7e5) is tried there, not the card's
55b5e34b: a wrong seed or a wrong passphrase? (`export` takes no
passphrase)``.

`verify`, `member`, `address` and `export` take no BIP-39 passphrase yet
(`--passphrase` is a usage error there; a prompt is a known open item),
so the right seed of a passphrase-protected seat derives other keys and
is refused as above. Leave such a seed out and confirm its seats by their
mk1 plates (in `verify`, also by their device records); for the hot seat,
give the hot child's own words in place of a passphrase-protected parent.
`create`'s closing checklist says so for each seed given with
`--passphrase`.

A seed of a letter that no seat of this card uses, other than the hot
entry's parent letter, is not refused. If the bundle list names its
letter (a Lightning seed, or a cheap wallet's parent), `verify`, `member`,
`address` and `member --for-spend` print `… fills no seat: the bundle list
names letter <L>; no seat of this card checks this seed` (`export` prints
no such line). Any other, such as another card's seed, is warned of in
every verb, `export` included: `seed <n> (letter <L>, fp <fp>) fills no
seat of this card: not checked here; verify it with its own card`. But
when seeds are given, none of them fills a seat or agrees with what fills
it, and at least one is not a seed the bundle list names, `verify`,
`member` and `address` refuse the run: `no given seed fills a seat of this
card or agrees with what fills it: a wrong seed, a wrong passphrase, or
another card's seed? verify each card with the seeds of its own seats`.
A run given only seeds the bundle list names, beside the plates, is not
refused. (The owner ruled for this reading on 2026-10-01, errata E50.)

On a card without fingerprints, a second seed of a keyed seat's letter
beside the one that derives the seat's key is only set aside, with its
own line (`seed <n>: seed <m> derives seat <i>'s xpub and is letter <L>'s
seed: set aside`), and does not fail `verify`.

Any warning prints before the refusal. `export` and `member --for-spend`
never refuse over a seed: they warn and keep it (`export` uses it for
`held` accounts). For a seed of a seat's letter that derives no seat's
key, `export` warns `… derives no seat's key: a wrong seed or a wrong
passphrase?` and `--for-spend` `… derives no seat's key: it signs
nothing here; a wrong seed or a wrong passphrase?`; a seat map engraved
wrong is warned of as `… the card's seat map is wrong for this seat; …`.
On a card without fingerprints `export` scans a disagreeing seed as one
more seating.

## `mr verify`

Re-read an engraved card and check it against ids, keys or seeds. With
keys or seeds it prints the seat each one filled (`plate 2 → seat @2`,
with the seat check `sc:…`), and for each seed the seat it filled or
agreed with (`seed 1 → seat @0`, `seed 2 → seat @1 (agrees with plate
2)`, `seed 1 → seat @2 (its child 24/0)`; a seed given twice, or the hot
child's own words beside its parent, agrees with what filled the seat:
`seed 3 → seat @1 (agrees with seed 2)`, `seed 3 → seat @0 (agrees with
seed 1's child 24/0)`), and fails on a stub mismatch or a seed that
fills no seat (see Keys and seeds). On a stub mismatch it says ``…: re-mint
that plate before engraving``, unless the plate's fingerprint is none
this card declares either: then ``…: a plate of another card, or minted
wrong: plate <k> looks like another card's plate (stub <s>, fp <fp>):
check that you hold this card's kit; re-mint a plate only if it is this
card's`` (`export` warns the same `plate <k> looks like another card's
plate …` line beside its stub warning, and goes on; `member` and
`address` refuse it with the same words, ending ``…; if it is this
card's, pass `--accept-stub-mismatch` to `mr <verb>` to use them``).

A seed no key confirms is refused naming the seats, singular or plural:
``seat @1 is not confirmed: give its device record or mk1 plate with `--keys```
(``seats @0, @1 are not confirmed: give their device records or mk1 plates
with `--keys```).

`--set-id` and `--digest` take the full 16 hex digits; any other length,
such as `export`'s 8-digit `[card …]` prefix, is a usage error (exit 2)
that says so and does not quote the value (for `--digest` it adds that
`export`'s `[card …]` shows only the first 8). `--against` compares like
with like: when neither card carries an xpub, or both carry xpubs and
fingerprints at the same seats, their ids; otherwise (one card keyed and
the other not, keys at different seats, or one without fingerprints)
the template ids, then each seat by its xpubs where
both carry one, else by the fingerprints both declare (``member (0, 0)
does not match the md1 card at seat @<i>: its fingerprint is <fp>, the md1
card's <fp>``) and their origin paths, since the same seed at another
path is another wallet (``member (0, 0) does not match the md1 card at
seat @<i>: its origin path is <path>, the md1 card's <path> (the same
seed at another path is another wallet)``; this is checked on every seat
the two cards do not key identically, one with neither an xpub nor a
fingerprint on either side included). A seat one card keys that the other neither keys nor
declares a fingerprint for is refused, not passed: ``member (0, 0) cannot
be compared with the md1 card at seat @<i>: the md1 card carries its
xpub, and this card neither keys it nor declares its fingerprint``.

### Synopsis

```sh
mr verify [OPTIONS] <mr1>...
```

### Flags

| Flag | Purpose |
|---|---|
| `<mr1>...` | The card's strings (one, or each chunk of a chunked card) |
| `--network <NETWORK>` | Network: main (default; `mainnet` is accepted too), signet, testnet or regtest [default: main] |
| `--set-id <ID>` | Fails unless the card's set id is ID (16 hex digits) |
| `--digest <D>` | Fails unless the card digest is D (16 hex digits, not `export`'s 8-digit `[card …]` prefix): proves this engraving |
| `--against <md1>` | Checks that member (0, 0) matches this md1 card (its strings in one value, separated by spaces) |
| `--keys <mk1…\|records>...` | Keys: mk1 plates (a chunked plate's strings in one value, separated by spaces) or `[fingerprint/path]xpub` records, each optionally `@i=`-bound |
| `--keys-file <file>` | A file of keys: one `@i=<card>` per line, chunked cards as consecutive strings |
| `--seeds <seeds>...` | Seeds, seed 1 first: each an ms1 plate or BIP-39 words; a seed's words separated by spaces, seeds separated by commas |
| `--seed-language <n>=<lang>` | The wordlist of seed n: `<n>=<lang>` (english, japanese, korean, spanish, chinese-simplified, chinese-traditional, french, italian, czech, portuguese) |
| `--accept-seed-language <n>` | Consent to use seed n in a language other than English |

## `mr decode`

Print everything an mr1 card holds: the template, delta and anchors,
set id, card digest, the (0, 0) policy id, stub and md1 card (as md1
chunks when it is over 80 symbols), the seat map, each seat's master
fingerprint from the Fingerprints TLV ("seat fingerprints: …"; "@i
none" for a seat the TLV leaves out, "@i none (00000000)" for one it
declares `00000000`, and "none" when the card has no Fingerprints TLV; the check §7a's lost-device
recipe asks for), the units, each slot
(its locks, what it removes and drops, whether it is open or a
lock-up), the set end, each slot's deadlines at epoch 0, and a bundle
checklist when the card lists other cards. On a card with a hot child it names the hot seat (``@3 is the hot seat (child 24/0 of seed A, letter K)``). It also prints the network the card is read on (``network: testnet, coin type 1``, as `member` does). Heights are dated from the anchor on mainnet and, roughly, on signet (``the dates are rough, since test chains do not keep 10-minute blocks``); on testnet and regtest they stay undated and one line says why. One chunk of a chunked card is refused as `repair` words it (``this string is chunk 0 of a 9-chunk card (chunks are numbered from 0), not a card on its own: chunks 1-8 are missing; give all 9 chunks together``). It takes no keys.

### Synopsis

```sh
mr decode [OPTIONS] <mr1>...
```

### Flags

| Flag | Purpose |
|---|---|
| `<mr1>...` | The card's strings (one, or each chunk of a chunked card) |
| `--network <NETWORK>` | Network: main (default; `mainnet` is accepted too), signet, testnet or regtest [default: main] |

## `mr repair`

Correct up to 4 substituted characters per mr1 string. A chunk set is
repaired as one card, atomically: one uncorrectable string fails the
whole call with no output. A mixed-case string, and a string over 93
symbols after `mr1`, are refused before any correction. Exit `0`:
nothing to correct; `5`: corrected (a repair report and the corrected
strings on stdout); `2`: not correctable.

It then reads the strings as `decode` would and says on stderr what
they are. A card: "the repaired card decodes: set id …, card digest
…" and the next step, "next: check it against the digest recorded for
this card, then engrave the corrected characters: `mr verify <the
strings> --network NETWORK --digest DIGEST`" (NETWORK is the
`--network` you typed, when you typed one; replace each word in
capitals). One chunk of a chunked card: "this string is chunk 0 of a
9-chunk card (chunks are numbered from 0), not a card on its own:
chunks 1-8 are missing; give all 9 chunks to one `mr repair` call".
Strings that pass the checksum but are no card: "the corrected string
passes the checksum but is not a card (…): check it character by
character against the engraving", since more than 4 errors can be
corrected to another valid string. The exit code is the checksum's
either way.

The report counts strings and positions from 0, and a position is a character after the `mr1` ("mr1 string 1: 1 correction at position 7" is the eighth character after `mr1` of the second string); when something was corrected, stderr adds ``note: string numbers and positions count from 0; a position is a character after the `mr1` ``.

`repair` corrects substitutions only. A string it cannot correct is
refused with "more than 4 substitutions, or a character left out or
added (which `mr repair` does not correct); the string cannot be
corrected: count its characters and check each against the engraving".
A single-string card given among a chunk set's strings is named ("string
i is a single-string card, not a chunk (every chunk string begins
`mr1l`): read it on its own, and give the chunk set without it"), and
arguments after an `mr1…` one that look like the groups of one string
split by the shell at its spaces (each not starting `mr1` and at most 12
characters) are refused naming that ("quote the whole string ('mr1… …
…') or give it without spaces"); a longer one is a string whose `mr1`
was misread, refused as that string, with its index. `decode` and the
other reading verbs say the same.

### Synopsis

```sh
mr repair [OPTIONS] <mr1 strings>...
```

| Flag | Purpose |
|---|---|
| `<mr1 strings>...` | The strings to correct (one card: one string, or its chunk set) |
| `--network <NETWORK>` | Network: main (default; `mainnet` is accepted too), signet, testnet or regtest [default: main] |

## `mr member`

Print one member (e, s) of the set as split-chain descriptors, an md1
card or a BIP 388 wallet policy. It runs every hand-out guardrail
(open, clamped, reorder, lock-up and its window, deadline, horizon),
prints the slot's description, lock dates, costs and minimum deposit,
and warns when one key alone spends. With `--for-spend` it prints the
member as the source of a sweep instead: `importdescriptors` JSON on
stdout and the step-by-step Core recipe on stderr.

`--as descriptor` prints its descriptors in `h` form, with the checksum
`export` prints for the same member. Each xpub in them is the card's
form (depth and parent fingerprint of no device's key), so it will not
match a device's or an mk1 plate's xpub text; plain `--as descriptor`
says so and names each seat's check to compare instead ("compare seat
checks: @0 sc:…, …"). `--as policy` heads the policy "policy (for
registration on a signer holding seat @0):", or "… holding one of seats
@0, @1):"; when your seeds fill some of those seats and plates fill the
others, it adds which are yours: "… holding one of seats @0, @1; your
seed: @1):".

A height the tip has reached prints as "(reached)" and an open row's lock
(height 1 or below) as "(any time, an open row)", never as a date (a date
extrapolated backward from the tip moves with the tip, and one for height 1
would predate the chain); a height still ahead keeps "(≈ date)". `member`
prints each deadline once. A slot or epoch out of range is refused with the
valid range: "slot 5 does not exist: the card has 2 slots; slots are 0 … 1"
(one slot: "its only slot is 0"), "epoch 20000 does not exist on this card:
the last valid epoch is 9,488 (spec §5)".

With `--for-spend` the stderr notes also list each path of the member
by what you gave: "path @1: your seeds sign it; opens 2034-08-28 (4.4
years)" (a wait under a year is in days: "opens 2026-10-01 (6 days)"), "path @0: nothing you gave signs it: it needs @0; open now"
(a relative lock after an absolute one adds ", then N days after each UTXO
confirms"; a path with a relative lock alone reads "opens N days after each
UTXO confirms"). A path
of a quorum names it as the role table does ("path 3 of @0, @1, @2, @3,
@4: your seeds sign it; open now"). A
co-signer is told its share and every way to finish: "path @0, @1, @2:
your seeds give 1 of the 2 signatures it needs; the rest: @0 or @2", or
"… the rest: any 2 of @0, @1, @3, @4". The spend recipe is commands, for bash, zsh, dash and fish alike, with
the capitals for you to fill in (a note first says that `bitcoin-cli`
carries the run's chain option, `-testnet`, `-signet` or `-regtest`, as
`export` prints it). Step (1) is `bitcoin-cli … -named createwallet
wallet_name=WALLET_NAME disable_private_keys=true blank=true
descriptors=true`, the `mr member … --for-spend --as descriptor … >
import.json` run that saves the JSON (the card, the network, epoch, slot
and tip, with `--keys MK1_PLATES` or `--seeds SEEDS` for the kinds of key
you gave), and `tr -d '\n' < import.json | bitcoin-cli … -rpcwallet=WALLET_NAME
-stdin importdescriptors` (`-stdin` takes one argument per line, so `tr`
puts the JSON on one line); under `--as policy` stdout is a policy, and
the step says the JSON is the descriptor form's. Step (2) is
`listunspent`. Step (3) gives each path's lock fields and, under them,
its `sendall` command: `-named sendall recipients='["DESTINATION"]'
options='{…}'`, with `"locktime"` for an absolute lock, `"inputs"` naming each
UTXO's `sequence` (one object per UTXO) for a relative lock, and `"psbt":true`
(the wallet only watches). Step (4) is the command `mr member CARD
--network N --epoch E --slot S --for-spend --as policy --height H --time T
--seeds SEEDS`, in either form (a plain `mr member --as policy` refuses an heir
past the deadline). Your
seeds sign; an mk1 plate beside them signs nothing (a kit's plates are
the seats whose seeds it lacks); a run given plates alone counts them
as its signers' devices. "key @i alone spends" names only such a
signer. The migrate-on-spend advice is printed on every run. When the
seeds you give are in no signing set of a path of slot 0 that is open
today, only of a later one (an heir's shape; a co-signer of a k-of-n is
in the open k-of-n's), one more line follows it: "if you are an heir
spending after the owner (…): sweep every UTXO with no change to a
wallet of your own, as step (3) above builds it, not to the current
epoch (§7a)". A run given no seed never gets that line. Whether the
seeds have that shape is read at the first epoch receivable for a lead
of at least 2,017 blocks, one past the short-delay threshold of 2,016
(or one second past 2,016 × 660 s of time), whatever
`--min-lead` is, so the line does not come and go with the lead.

## `mr address`

## `mr current`

Find the nearest epoch whose every absolute lock, in slot S (default
0), is at least a lead L away, each kind in its own units (a block
counts 9 minutes). Locks set by `open` are ignored; a slot with no
other absolute lock is measured by the card's deadline functions, and
the answer then changes only the branch. Without `--slot`, each
own-wallet row is answered too (`wallet at slot s: epoch E`).

It prints the answered member's nearest absolute lock with its date and
the lead it gives (``slot 0 at epoch 3: deadline height 1,417,680
(≈ 2031-05-02); lead achieved 2,770 days``; none on an epoch-less card,
which keeps its fixed text). It also prints, for each path of the
answered member with a relative lock, `path <keys> opens about N days after each deposit confirms`,
warning when that wait is shorter than your lead, and the migration
rule: every row's funds move to the same slot of the new epoch, and
only an open row's go to slot 0.

It never offers a lead below `--min-lead`: a `--lead` below it is
searched at `--min-lead`, with the warning ``--lead L is below
--min-lead M: the lead used is M, since `current` never offers a lead
below --min-lead (§7)``, so the epoch it answers is one whose
deadlines `address` accepts at the same `--min-lead`, in whole days
(`address` also runs its open, lock-up and horizon checks). The
warning for a path that opens before your lead compares with the lead
used.

It refuses when no epoch meets the lead: `no epoch of slot S meets
lead L; a lead of at most <L′> still reaches epoch <E>` while one
still meets `--min-lead`, else `this slot ends at <date>; move to a new
set on new origin paths`. Past the heir's default scan it answers the
last epoch of the scan and prints the lead achieved (`lead 9.4 years:
the most the heir's default scan covers`), or refuses `this slot ends
within the heir's scan: move to a new set` when that lead is below
`--min-lead`. An epoch-less card answers epoch 0 for any lead. At a
tip past 2038-01-19 a slot whose member carries a time lock has no
epoch, and `current` answers only the other slots, saying for the
others to move the funds to a new set on new origin paths. It takes no
`--compromised` and prints no reminder.

### Synopsis

```sh
mr current [OPTIONS] --height <H> --time <T> --lead <L> <mr1>...
```

### Flags

| Flag | Purpose |
|---|---|
| `<mr1>...` | The card's strings (one, or each chunk of a chunked card) |
| `--height <H>` | The tip's block height |
| `--network <NETWORK>` | Network: main (default; `mainnet` is accepted too), signet, testnet or regtest [default: main] |
| `--time <T>` | The tip's median time past, unix seconds (any u32) |
| `--accept-tip` | Accept a tip whose height and time disagree with this release's anchor by more than 180 days |
| `--lead <L>` | The lead: how far every absolute lock must be from the tip (2y, 26w, 30d, 36h; a bare number is days; a block counts 9 minutes) |
| `--slot <S>` | The slot S (default 0; without it, each own-wallet row is answered too) |
| `--min-lead <L>` | The minimum lead: never offers a lead below it (default 30 days) [default: 30] |
| `--beyond-horizon` | Answer an epoch beyond the heir's default scan |

### Worked example

```sh
mr current mr1… --network testnet --height 1000000 --time 1900000000 --lead 5y
# tip = 1,000,000, ≈ 2030-03-17; this must be the current tip
# slot 0: epoch 1
# funds at slot 0 migrate to slot 0 of epoch 1; every row keeps its slot, …
```

## `mr create`

Issue a new mr1 card from a template or preset: its keys, a slot table
and a tip. `create` runs every guardrail before it mints anything, and
refuses mainnet while the derivation path is provisional. It never
generates a seed: every seat's key comes from `--keys` (in the numbering
the template was typed in), except the hot seat's, which it derives from
the hot child.

another path is refused (`--lockup-no-window`) with one line per pair
of paths, its epochs merged into ranges and its windows into their
least and greatest: `slot 1, epochs 0-9489: the @0 path opens 1,000

a seat of that card, at the key's origin path, that it is identified
with:

- `@i=<key>` binds seat i;
- an unbound key goes to the seat at its origin path whose Pubkeys TLV
  key it is; else to the one open seat there whose declared master
  fingerprint it carries; else, once those are placed, to the one open
  seat left there that it may be. An open seat has no key yet and no
  Pubkeys TLV key; a key may be an open seat's when that seat declares
  its fingerprint or none, or the key carries none (a declared or
  carried `00000000` counts as none);
- unbound keys that may each be several open seats' keys at their path
  fill, in any order, every open seat there that one of them may be,
  each key a seat of its own (the seats are then keyed, but none is
  identified; an open seat that none of them may be, since it declares
  another fingerprint, stays unknown). Fewer keys than those seats are
  refused as undecidable: give every key of that path, or bind each
  with `@i=`. Keys that cannot each take a seat of their own among those
  seats are refused: one of them is not that card's key;
- refused (exit 1): a key whose origin path is not its bound seat's, or
  no seat's; a seat the card lacks; a key whose master fingerprint is
  not the one the card declares for its seat, or none it declares for an
  open seat at its path (a key that carries no fingerprint, or
  `00000000`, is never refused for it, since it decides nothing); a key
  that contradicts the card's own Pubkeys TLV key for its seat; more
  keys at a path than the card has seats there; a key given twice for
  one card.

So on a card whose seats share a path (a BIP 48 multisig's
`m/48'/1'/0'/2'` for every seat), give every key of that path, in any
order, or bind each with `@i=`, unless the keys carry the fingerprints
the card declares. The collision test compares every key known for a
given card against every seat of the new card, whichever seat it went
to. It then tests every seat of the given card at a new seat's path by
master fingerprint, its key known or not, when both cards declare one
for it other than `00000000` (which counts as none, and two `00000000`
are not the same fingerprint): the same fingerprint collides, different
ones do not. A seat whose key is unknown and that no two fingerprints
decide is tested by its seed letter when both cards have seat maps (an
`mr1` card), else refused as undecidable. A collision names the seat the
key is identified with, or, for keys that filled a path's
undistinguished seats, those seats ("seat @0 or @1"). A seat's
identified key is a `--sibling-keys` key identified with it, else the
given card's own Pubkeys TLV key for it: an `mr1` card that carries its
keys needs no `--sibling-keys` for the checks below. The letter-reuse
warnings read a key only where it is identified with its seat, and a
declared `00000000` (on either card) as no fingerprint. The hot/cold
check across the given cards reads each seat's fingerprint, else its
identified key: a hot child that derives a cold seat's key is refused,
with no override, whether that key came from `--sibling-keys` or from
the card's Pubkeys TLV; a seed of the new card that derives a given
card's hot-seat key is refused the same way; and that key confirms the
card's hot parent, for the own-card question and `--hot-on`. A given
md1 is checked too, every one of its seats cold (it has no hot seat): a
hot child whose master fingerprint the md1's Fingerprints TLV declares
at a seat, or that derives a seat's key from `--sibling-keys` or from the
md1's Pubkeys TLV, is refused with no override ("hot child 24/0 of seed
A fills md1 1a2b3c4d's seat @2: …", the md1 named by its 8-digit id
prefix), and one that derives a key that filled a path's
undistinguished seats is refused on those seats, with no `--hot-on`
route; where nothing decides, no refusal and no letter line prints,
since an md1 has no letters (its seats are listed instead, below). In
`upgrade`, whose hot child is the md1's own, these refusals end
"`upgrade` keeps the md1's hot child, so this md1 cannot be upgraded
with that card beside it: move that card's funds and give it up, or
move this md1's funds with `create`, whose search takes another child"
in place of "let the search take another child". The md1 that
`upgrade` upgrades, given back, is set aside and not checked (below:
the same descriptor, every key identified with a seat equal to that
seat's key), or refused when nothing tells it from another wallet's
identical card (below); another wallet's md1 on the same template and
paths, its keys in other seats, is checked like any given card. On a
run given `--hot-child` (in `create` or `upgrade`, with or without
`--hot`), each given md1 with a seat that nothing decides gets one
line naming those seats: "the cross-card hot/cold check was not
possible for md1 1a2b3c4d's seats @1 and @2: no fingerprints and no
`--sibling-keys` tie them to the hot child (§5c)". A seat is decided
by a fingerprint its Fingerprints TLV declares (`00000000` is none),
by its key from `--sibling-keys` or its Pubkeys TLV, or by keys that
filled its path's undistinguished seats; such a seat is not listed.
One md1 given twice (as `--sibling` and `--bundle-card`, say) is one
card: one line, at its first appearance, listing a seat only if no
occurrence decides it. The md1 that `upgrade` sets aside is not
listed, and a run without `--hot-child` has no hot child and no such
line. The hot/cold check also reads keys that filled a path's
undistinguished seats of an `mr1` card: a hot child that derives one
of them is refused on those seats, or, when that card's hot seat is
among them, refused as undecidable (bind each with `@i=`) unless
`--hot-on` names that card; a seed of the new card that may be that
card's hot child the same way is refused as undecidable; and such keys
do not confirm the card's hot parent (the own-card question's "no" and
`--hot-on` say to bind each with `@i=`).

## `mr upgrade`

Issue an mr1 card whose member (0, 0) is the wallet of an existing md1
card, so the wallet you already funded becomes the card's first member.
`upgrade` is `create` over the md1 card's descriptor, in the md1's own
numbering (`@i` is the md1's `@i`): the template, the origin paths and
the path convention's rounds are the md1's, and every other rule,
guardrail and print is `create`'s. It refuses mainnet while the
derivation path is provisional, and never generates a seed.

### Synopsis

```sh
mr upgrade [OPTIONS] <md1 card>...
```

| `--accept-set-end` | Accept a slot or time delta that ends before the tip plus the horizon |
| `--accept-anchor` | Accept an anchor before the tip or beyond the tip plus the horizon |
| `--own-wallet <s,…>` | Mark rows as their own wallets (slots, comma-separated) |
| `--role <name=role:seeds>` | A participant: `<name>=creator\|heir\|cosigner:<seeds>` or `<name>=helper`; one per participant (a shared letter's seeds as `<letter>#<fingerprint>`) |
| `--seeds <seeds>...` | Seeds, seed 1 first: each an ms1 plate or BIP-39 words; a seed's words separated by spaces, seeds separated by commas |
| `--seed-language <n>=<lang>` | The wordlist of seed n: `<n>=<lang>` (english, japanese, korean, spanish, chinese-simplified, chinese-traditional, french, italian, czech, portuguese) |
| `--accept-seed-language <n>` | Consent to use seed n in a language other than English |
| `--passphrase <n>=<passphrase>` | A seed's BIP-39 passphrase, by input position (`<n>=…`) or by a letter one given seed has |
| `--accept-12-word <n>` | Accept 12-word seed n |
| `--no-fingerprints` | Leave out the Fingerprints TLV (refused for an md1 card that has one, and for a wallet whose seeds share a letter) |
| `--horizon <years>` | The heir's default scan horizon in years (11 … 31; 10 is the default, written by omitting the field) |
| `--bundle-card <mr1\|md1>` | A bundle card (mr1 or md1): the list names it, and it is a sibling too; repeat for each |
| `--bundle-account <seed:purpose:n>` | A bundle account `<seed>:<purpose>:<n>` (a letter or `held`) |
| `--hot-child <letter:12\|24>` | Derive the hot child from the seed with this letter: `<letter>:<12\|24>` |
| `--hot <@i>` | The hot seat (`@i`): the hot child fills it |
| `--hot-on <set-id>` | Share the hot device with a given card (its set id or 32-bit prefix) |
| `--retire-child <letter/12\|24/i>` | A retired child of the parent: `<letter>/<12\|24>/<i>` |
| `--first-hot-child <letter>` | Attest that this is the parent's first hot child |
| `--compromised <set-id>` | Declare a given card compromised (its set id or 32-bit prefix) |
| `--hot-cold-seed` | Accept a seed on a short single-key path and in a quorum of one template |
| `--heir-holds-hot-path` | Admit an heir role listing `hot` whose spend-today test fires only with the hot seat |

Mandatory: the md1 card, the tip (`--height`, `--time`), a slot table
(`--slots` or `--preset`), a `--role` per participant, the sibling
question (`--sibling …` or `--no-other-cards-on-these-paths`), and a key
for every seat the md1 carries no xpub for, as `--keys @i=<key>` in the
md1's numbering. A seat the md1 keys takes the md1's xpub; a key given
for it must be the same. `upgrade` has no `<template>`,
`--template-preset`, `--round` or `--min-deposit`.

**The witness.** An md1 with any seat it does not key needs a witness of
the funded seating: `--witness-md1` (a keyed md1 of the wallet),
`--witness-descriptor` (either chain, or the `<0;1>` pair) or
`--funded-address <addr> --index I [--change]`. The keys, the hot
child's included, are seated by §4's seating rule as the heir runs it
on the new card, with the fingerprints the card carries; a key the rule
would seat elsewhere is refused ("an heir would seat it wrong"). That
happens only on a card without fingerprints, where two seats at one
origin path are seated by canonical order: the refusal tells you to drop
`--no-fingerprints`, so each plate is seated by its fingerprint, or to
`create` a card on a new account. The witness must show member (0, 0)
under that seating; otherwise `upgrade` refuses, printing the witnessed
seating beside the rule's and the fix its shape shows: an address the
rule's seating derives on the other chain ("…: add `--change`" or
"drop `--change`") or at another index below 1,000 ("…: rerun with
`--index 7`"); keys the witness shows bound otherwise, where the
bindings could have chosen that seating (the seats share an origin path,
the md1 declares no fingerprint that tells them apart, and the md1 keys
neither, since `upgrade` keeps the md1's own keys: "if `--keys`'
`@i=` bindings are mistyped, bind each key as the witnessed seating
does"); and otherwise "the fix is a new md1 card or `create` on a new
account", since the wallet was funded under another seating. Other
seatings are searched up to 6 seats; past that the refusal says
"witnessed seating not searched (more than 6 seats)" and asks you to
check the `@i=` bindings, where two seats could swap keys (and, for an
address, `--funded-address` and `--index`), before the new card. A witness at `--index` 1000 or more draws the warning `address` gives
for such an index, and adds that the heir needs `--history` or `--next`
to reach it. A witness is named by its flag in a refusal, never
quoted. A fully keyed md1 needs none: `upgrade` derives its own
addresses.

**What it checks and prints**, before the card: every refusal of the md1
and its witness comes before any line (an `mr1` given as the md1, a hash
fragment, a repeated placeholder, an origin that is unspecified,
`--no-fingerprints` on an md1 that carries fingerprints). Then, after
the "(0, 0) md1 card:" block: "(0, 0) check: member (0, 0) decodes to
the md1 card's descriptor, template id X"; the policy id, unchanged or
changed only by the Fingerprints TLV `upgrade` adds (then it also tells
you to re-mint every mk1 plate with its origin fingerprint); the witness
line; whether the card's payload P equals the md1's bits, and why not;
the seats told apart only by fingerprint; and (0, 0)'s deadlines with
dates. When a (0, 0) deadline is past, or less than `--min-lead` after
the tip, it says every coin at (0, 0) is spendable by the heir path (now,
or from a date) and prints the three commands of the §7a sweep
(`current`, `address`, `member --for-spend --as descriptor`), each with
the new card's strings, `--network` (on every network) and the `--height` and
`--time` you gave; you fill in the receiving epoch `E` and the index
`I`, and the keys `MK1_PLATES` when the card has a seat it does not key. A
height deadline at the tip counts as past, since the heir path spends
in the next block (the (0, 0) block reads ``deadline: height 320,000 (reached): past (spends in the next block)``, not "closer than --min-lead"); a time deadline counts as past only before the tip's
time. The card is issued all the same. An heir whose kit spends (0, 0)
today, when the first receivable epoch is later, is warned, not
refused.

**Hot child.** The hot flags work as in `create`. The hot seat's key
must be the md1's: when the md1 keys the hot seat, or declares its
master fingerprint, the child the search takes must match, or `upgrade`
refuses (`` `@i`, the hot seat: … `upgrade` keeps the md1's keys ``;
check `--hot-child`, the history inputs and the parent's passphrase).
An heir listing `hot` is rerun at epoch 0 as well as at the first
receivable epoch, and needs `--heir-holds-hot-path` wherever the hot
seat makes their kit spend today. `--hot-child L` is refused when two
seats of letter L carry different fingerprints, or a role lists `L#…`.
`--hot-on` beside a given card of a newer child of the parent, or of
the other length at the same index, is refused as in `create`, but the
refusal ends "`upgrade` keeps the md1's hot child, so this md1 cannot
be upgraded on that device: move its funds with `create`, whose search
takes a new child" in place of "let the search take a new child".

`upgrade` admits two seeds that share a letter (seated by the Fingerprints
TLV, so `--no-fingerprints` is refused for them); a role then names each
as `<letter>#<fingerprint>`. The md1 given back, as `--sibling` or
`--bundle-card`, is set aside with a note and is neither listed nor
counted in the bundle list (or refused, as below). The note says it is the card being upgraded
when every seat's key is known (from its keys or `--sibling-keys`) and
equal to the seat's, with no fingerprint that differs: the keyed md1
itself, or a keyed copy of it (the same template and origin paths). A
key identified with a seat (bound with `@i=`, the card's own Pubkeys
TLV key, or placed by the fingerprint the card declares for that seat)
must be that seat's key: a mirror wallet, whose card keys the heir's
key at @0 and the hot child at @1 where the md1 has them the other way
round, is another wallet and is refused as one key on two cards. Only
keys given unbound at a path several seats share, whose seat nothing
tells, are compared as a set, in any order, and only on a card with
the md1's own payload: a card of another payload (no Fingerprints TLV
where the md1 has one, say) with such keys is tested as a sibling;
bind its keys with `@i=` to have them compared seat by seat. Even on
the md1's own payload, such keys are trusted only where the
fingerprints the card declares tell those seats apart (each seat
declares one, all different). An md1 without fingerprints, given back
with its keys unbound at a path two or more seats share, is byte for
byte another wallet's card with those keys in other seats (a mirror
wallet whose cold seat holds the hot child, or two cold seats
swapped), so it is refused, with no override: "`--sibling` md1
1a2b3c4d has the payload of the md1 being upgraded, but its
`--sibling-keys` fill its seats @0 and @1 at m/48'/1'/0'/2' unbound, so
nothing tells it from another wallet with those keys in other seats:
bind each with `@i=`, or leave the card out". Bound with `@i=` to its
own seats, it is set aside; left out, the run is the same. An
md1 with the md1's own payload and a seat whose key is unknown is set
aside too, when no key you give for it with `--sibling-keys` differs
from the seat's (at a shared path, when each is one of that path's
seats' keys, placed as above; a partial set of unbound keys that
nothing places is refused, as for any card); its note says only that it has the same
payload as the md1 being upgraded, since another keyless wallet on the same template
and paths, without fingerprints, has that payload too. Any other given
md1 is tested as a sibling, even one with the same payload: a key that
differs makes it another wallet (kept in the bundle list as a bundle
card), a shared key is refused as one key on two cards, and a seat that
cannot be decided asks for `--sibling-keys`. An md1 of the same
template, origin paths and fingerprints but with a seat whose key is
unknown (a keyless copy of a keyed md1, say) that collides is told so:
"… has the md1 being upgraded's template, origin paths and
fingerprints, but not every seat's xpub: if it is a copy of that md1, it is not its
own sibling: drop it from `--sibling`, or give its keys with
`--sibling-keys` so `upgrade` sets it aside; if it is another wallet on
these keys, the fix is `create` on a new account". An mr1 card given as
`--sibling` whose set id and digest are those of the card this run mints
is that card (an owner re-minting a lost card gives the one they still
have): it is set aside with the note "it is this card (same set id and
digest): not its own sibling (§7): set aside", and is not refused as a
collision; an mr1 card of another set id or digest on the same keys still
collides. Each kit's notes
give each seat's origin path as the card has it: the md1's own path
(such as `m/48'/1'/0'/2'`), or the path convention's when the md1's
paths are the convention written out.

## `mr export`

Export watch-only descriptors for a wallet or an heir: every member of
the chosen epochs and slots, each labelled with (e, s) and its unlock
heights or dates (a path of a quorum names it as the role table does:
"3 of @0, @1, @2, @3, @4 any time"), as ready `bitcoin-cli scantxoutset` calls in windows of
1000 indexes (main calls over indexes k·1000 … k·1000 + 999, probe calls
over the top 100), batched at 1,000,000 scripts per call (1,000
descriptors a main call, 10,000 a probe call). Each call is one line,
`printf '%s\n' '<json>' | bitcoin-cli -testnet -stdin scantxoutset start`
(the run's `--network` as Core's chain option, first: `-testnet`,
`-signet` or `-regtest`, none on `--network main`), which
bash, zsh, sh (dash) and fish all run (fish has no here-documents). The
`printf` builtin feeds the call's JSON to Bitcoin Core's `-stdin`, which
reads it as the call's last argument, so no shell argument limit splits
a call, and the single quotes keep the shell from expanding anything in
it (the JSON never holds a `'` or a `\`: `export` refuses to print one
that does). Every `bitcoin-cli` command `export` prints carries that
chain option (the scan and import calls, and the `createwallet`,
`rescanblockchain` and `getwalletinfo` texts), so a call run as printed
reaches the run's `--network`; add any connection options of your own
(`-datadir=…`, `-rpcport=…`) before `-stdin`. Stdout and the heir file
(its second line) say `network: testnet, coin type 1`, as `member
--for-spend` does. When the run prints calls (a refused run prints the
network line alone), on testnet one more line says ``network testnet:
each `bitcoin-cli` call here carries `-testnet`, testnet3's option; on a
testnet4 node write `-testnet4` in its place (Core v28 or later), unless
your bitcoin.conf selects the network (next line)`` (`mr`'s testnet keys
and addresses are testnet4's too), and on every network but main three
lines say ``bitcoin.conf: if yours selects testnet or testnet4 (a
`chain=test` or `chain=testnet4` line, or `testnet4=1`), Core refuses a
second choice: "Invalid combination of -regtest, -signet, -testnet,
-testnet4 and -chain. Can use at most one."``, ``bitcoin.conf: then drop
`-testnet` from each call here, and the file's choice applies`` and
``bitcoin.conf: if yours selects another network (another `chain=` line,
or a line such as `signet=1`), do not drop `-testnet`: that node is on
another network than this run, and a scan there would read the wrong
chain`` (on signet, "selects signet (a
`chain=signet` line)", "`testnet4=1`" and `-signet`; on regtest,
"selects regtest (a `chain=regtest` line)", "`signet=1`" and
`-regtest`): `bitcoin-cli` reads `bitcoin.conf` and picks the chain
before it runs anything, and Core takes at most one chain choice from
the command line and the file together, so a `chain=` line refuses the
printed option even for the same network (a `signet=1` line beside
`-signet` is the one agreeing pair). Dropping the option helps only when
the file selects the run's network (a testnet4 node counts for
`--network testnet`); a file that selects another network means the node
is on another chain, and the calls belong on a node of the run's
network. A descriptor
parse error, the footer says, means ``the node is on another network
than the card (testnet: run the calls as printed, against a testnet
node) or too old for the descriptor: rerunning cannot help, so check
the node's network (`getblockchaininfo`'s `chain`), then upgrade the
node``. A call line can be hundreds of kB, and an
interactive shell can cut a long pasted line short (dash keeps 4,095
bytes; bash's readline usually takes it whole), and pasting it into a
file is cut the same way, so `export` prints a note before the calls,
on stdout and in the heir file: do not paste it; `grep '^printf ' FILE
> calls.sh` copies the call lines (each starts `printf `) from FILE, the
heir file or the output saved with `> FILE`; delete the lines you do not
want run, and run `sh calls.sh` or `fish calls.sh` (with `--history`, whose
import calls hold the `WALLET_NAME` placeholder, "replace WALLET_NAME, and run").
The heir file itself is not a script: do not run it. The output
begins with each card's bundle list as a checklist. With `--seeds` it
also derives the bundle list's accounts (the cheap hot wallet included,
with its first address and restore text) and, unless
`--no-child-discovery`, the child discovery accounts. It never refuses
over a tip: the tip check is a warning.

### Synopsis

```sh
mr export [OPTIONS] <mr1>...
```

### Flags

| Flag | Purpose |
|---|---|
| `<mr1>...` | The card's strings (one, or each chunk of a chunked card) |
| `--card <mr1>` | Another card of the bundle, scanned with the same keys or seeds (a chunked card's strings in one value, separated by spaces); repeat for each card |
| `--network <NETWORK>` | Network: main (default; `mainnet` is accepted too), signet, testnet or regtest [default: main] |
| `--keys <mk1…\|records>...` | Keys: mk1 plates (a chunked plate's strings in one value, separated by spaces) or `[fingerprint/path]xpub` records, each optionally `@i=`-bound |
| `--keys-file <file>` | A file of keys: one `@i=<card>` per line, chunked cards as consecutive strings |
| `--seeds <seeds>...` | Seeds, seed 1 first: each an ms1 plate or BIP-39 words; a seed's words separated by spaces, seeds separated by commas |
| `--seed-language <n>=<lang>` | The wordlist of seed n: `<n>=<lang>` (english, japanese, korean, spanish, chinese-simplified, chinese-traditional, french, italian, czech, portuguese) |
| `--accept-seed-language <n>` | Consent to use seed n in a language other than English |
| `--height <H>` | The tip's block height (with --time): the default scan, epochs 0 … e_hi |
| `--time <T>` | The tip's median time past, unix seconds (with --height) |
| `--horizon <D>` | The horizon in years (default: the card's horizon field, else 10) |
| `--epochs <a..b>` | Scan epochs a … b (inclusive) instead of the default range |
| `--exhaustive` | Scan every valid epoch |
| `--next <k[:target]>` | Emit window k of the run (k ≥ 1, or 0 with a target; at most 2,147,482), optionally narrowed to targets, repeated with one k: `[<digest prefix>:]<e>/<s>` (the prefix 8 to 16 lower-case hex digits), or a bundle entry (`held:84:0`, `C:84:0`, `A/24/0:86:0`) |
| `--history` | Check history, spent or not: the gap-20 address-index output and the Core rescan, instead of the quick scan |
| `--child <n>=<letter>/<12\|24>/<i>` | Declare given seed n to be the child `<letter>/<len>/<i>` a bundle entry names (e.g. `2=A/24/0`), as a `hot` kit's child plate reads |
| `--try-seatings [<K>]` | Export every seating of the undecided seats, up to K! of them (default K = 4, i.e. 24) |
| `--heir-file <file>` | Also write window 0's calls, headed by the set id, card digest, tip, horizon and epoch range, to this file: a fallback that needs no `mr` (it holds every descriptor, so every address) |
| `--no-child-discovery` | Leave out the child discovery scan (account 0 of each given seed's BIP-85 children 0 … 15, both lengths, four purposes) |

A card with an epoch axis needs one of the tip (`--height`, `--time`),
`--epochs a..b` or `--exhaustive`; an epoch-less card defaults to
`--epochs 0..0` and refuses any other range. `--exhaustive` can write hundreds
of megabytes: when its stdout passes 1 MB, a stderr warning first says how
large ("`--exhaustive` writes about 956 MB to stdout (302 call lines): save it
with `> FILE` rather than printing it, then `grep '^printf ' FILE > calls.sh`
copies the calls"). Beside every probe call
`export` prints the ready `mr export SAME_ARGUMENTS --next <k + 1>`
command (SAME_ARGUMENTS: this run's arguments): run it while a probe call finds any unspent output. Each card
prints the rule's `@i=` binding list after its set id and a seating
count with its scan time; seatings the card cannot decide (seats at one
origin path with nothing to tell their plates apart) are exported only
with `--try-seatings`, each labelled with its binding list and a ready
`member --for-spend` stem (`mr member MR1_CARD --network testnet
--for-spend --epoch EPOCH --slot SLOT --seeds GIVEN_SEED_1 --keys
@1=PLATE_2`: the run's `--network`, a seed by its position in `--seeds`,
a key by its label), and a count above K! is refused with its scan
time. `--next` may be repeated with one k, each value naming a target
(`--next 1:0/0 --next 1:held:84:0`): the run emits the union of the
targets' descriptors; two different k are refused. `--history` leaves
the child discovery accounts out; a discovery account prints its own
`--history --next 0:<entry>` command, and `--history`'s ready
next-window command keeps the run's targets. The Core rescan's imports
are printed the same way, `printf '%s\n' '<json>' | bitcoin-cli
-testnet -rpcwallet=WALLET_NAME -stdin importdescriptors` (up to 1,000
descriptors each), and the rescan rule's calls as `bitcoin-cli -testnet
-rpcwallet=WALLET_NAME rescanblockchain` and `bitcoin-cli -testnet
-rpcwallet=WALLET_NAME getwalletinfo` (Core refuses a call without
`-rpcwallet` while more than one wallet is loaded), after the line ``in each `bitcoin-cli` call, replace
WALLET_NAME with the name of the watch-only wallet created for this
scan (`createwallet wallet_name=WALLET_NAME`, above)``. `WALLET_NAME` is
a plain word in every shell, so a line pasted unedited only fails in
Core (no such wallet); `<name>` there was a redirection from a file.
A seventeenth seed is
refused: run `export` once per group of at most 16 seeds.
`--heir-file` warns on stderr that the file holds every address of the
set. A new file is created readable by its owner only (mode 0600 on
unix); a regular file of your own already at that path is made 0600 and
replaced, and the run says so ("heir file written (the `--heir-file`
path, replacing the file that was there)"). A FIFO or device there is
written to as it is, its mode untouched; a symbolic link is followed and
the same rule applies to its target. The path is checked before
anything is printed: a folder, a link to nothing, a socket, a path in
no existing folder or in a folder you cannot write, a file, FIFO or
device you cannot write, and a regular file of another user (root
included: `mr` does not take another user's file over) are each
refused, naming `--heir-file`. An `--epochs a..b` whose start is past
the last valid epoch of any given card is refused before any line; an end past it is warned of
and the range line says "(--epochs, clamped to the card's last valid
epoch L)". The file covers the whole run, so it is refused with a `--next`
target; with `--history` it holds window 0's main and probe calls and
then both history outputs.

A run that **scans none of a card's members** (a lost plate, a seed
given without its seat's plate, plates made for another network, only
undecided seats) is refused, exit 1, even when it still has bundle or
child discovery accounts (`--seeds` alone always brings discovery
accounts): those accounts are never used for seating and do not stand in
for the card's members. Before the refusal each card names every missing
seat and what fills it, "card 1: seat @1 (letter B, fingerprint …,
origin m/…) is missing: give its mk1 plate with `--keys`, or seed
B with `--seeds`" (`export` takes mk1 plates as keys, no record; the hot
seat also by its parent or `--child`, or, when a seed of the parent's
letter was given, "seed A was given, but its child is not this seat's …:
give the child's own words with `--seeds` and `--child N=A/24/0`"; the
same lines are warnings on stderr when stdout is redirected, so a terminal shows each once), and
says when plates were set aside ("… (check `--network`) fills no
seat"). The refusal reads "nothing to export for card 1: no member of it
derives from the keys and seeds given …"; to scan only a bundle or
discovery account, name it with `--next 0:<entry>` (an entry as the
checklist prints it, such as `A/24/0:86:0`, or a discovery account's
`<letter>/<len>/<i>:<p>:0`). A run left with no descriptor is refused
the same way: when every member the run names is invalid ("card 1: no
member is valid in epochs … ", or "… the `--next` targets name"), and
under `--history`, which leaves the discovery accounts out, when they
were all it had. With several cards (`--card`), one card's missing seat
refuses the whole run, its fully seated cards included: give the missing
seats, or leave that card out of the run. A refused run prints no scan
call, no discovery count line, and writes no `--heir-file`; since
`--heir-file` is refused with a `--next` target, a heir file of the
accounts alone cannot be written while a seat is missing (scan an
account with `--next 0:<entry>` without `--heir-file`). A card with no
valid member beside cards that scan is named on stdout and as a warning
("card 1: no member the `--next` targets name is valid"). A call whose
JSON would pass Bitcoin Core's 32 MiB request cap is split (only a probe
call of very long descriptors can), and one whose single descriptor
would pass it is refused (no card reaches it).

A cheap-wallet (child) entry's wallet is printed only from a parent
whose BIP-85 child has the entry's child letter and, where the card
declares the hot seat's fingerprint, that fingerprint. The hot child's own words, given without `--child` and seated at the
hot seat by the card's fingerprint, are the entry's source ("seed 1 (the
hot seat's own words, fp …; it filled hot seat @3 by the card's
fingerprint)"). A parent given
without its passphrase (`export` takes none) derives another child: its
wallet is not printed, and `export` says so on stdout ("…
it is not this entry's child, so its wallet is not printed; seed <n> is
not this card's parent, or its passphrase is wrong …: give the child's
own words with `--seeds` and `--child N=C/24/0`"). Stderr says it once
for the seed, in the seating's warning that names the letters ("seed 1
has letter C but its child 24/0 has letter H, not F: seed 1 is not this
card's parent, or its passphrase is wrong …"), not three times. The fingerprint is
checked only on the hot seat's own entry; a cheap-wallet-only entry, and
any entry on a `--no-fingerprints` card, is checked by its letter alone,
so a wrong parent whose child shares the letter (1 in 16) still prints.

### Worked example

```sh
mr export mr1… --network testnet --keys mk1… mk1… --height 1000000 --time 1900000000
# tip = 1,000,000, ≈ 2030-03-17; this must be the current tip
# network: testnet, coin type 1
# card 1: set id 0bcbf7c84ecc9a8b, card digest 01a0adbdf3d19c6e
# rule: @0=plate 1, @1=plate 2
# horizon: 10 years (the default)
# epochs 0 … 7 (the default scan: e_hi at this tip and horizon); …
# seat @0: confirmed by plate 1
# seat @1: confirmed by plate 2
# seatings: 1: 16 descriptors, 17,600 scripts per window, about 63 s
# network testnet: each `bitcoin-cli` call here carries `-testnet`, testnet3's option; on a testnet4 node write `-testnet4` in its place (Core v28 or later), unless your bitcoin.conf selects the network (next line)
```
