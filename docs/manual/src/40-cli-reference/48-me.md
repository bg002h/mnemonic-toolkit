# `me` (me-cli) reference

<!-- cspell:ignore NDEF BOOTSEL picotool UF2 Tails sidecar systemwide -->

The host CLI of mnemonic-engrave: it prepares wallet backups and signed
transactions for a SeedHammer II. `me` owns no card format (see
[Which tool owns which verb](#which-tool-owns-which-verb)); it validates
constellation strings made by the other tools and packs them for the
machine. Its surfaces:

| Surface | What it makes |
|---|---|
| [`me` with no subcommand](#me-converter) | the NFC converter: one public `md1`, `mk1` or `mt1` string → an NDEF payload |
| [`me bundle`](#me-bundle) | a plate manifest (JSON) and a checklist for a wallet backup's public strings |
| [`me sysw pack`](#me-sysw-pack), [`wipe`](#me-sysw-wipe), [`show`](#me-sysw-show) | the *systemwide* (`sysw`) container that the machine's Load Payload reads: transactions (from [`mt`](#mt-mt-cli-reference)), wallet backups, descriptors, composer records |
| [`me seal`](#me-seal) | a Sealed Payload (a UF2 image) for the machine's Sealed Payload program |
| [`me hash`](#me-hash) | the public-data hash of a Sealed Payload, re-derived from your own cards |

`sysw` and `seal` are different containers in different flash regions,
read by different programs on the machine, and kept apart on purpose.
When the machine refuses a Sealed Payload, see
[When the SeedHammer II refuses a payload](#when-the-seedhammer-ii-refuses-a-payload).

This chapter describes `me 0.13.0`, built from mnemonic-engrave's
default branch. Every subcommand accepts `--help` (`-h` prints a
one-line summary of each flag, `--help` the full text); each Flags table
quotes the summary.

:::danger
The phrase `abandon abandon … about` used below is the canonical BIP-39
test vector. It is **public**: any wallet derived from it has been swept
by chain watchers. **Never engrave it. Never fund it.** The md1 and mk1
strings below are that phrase's BIP-84 bundle from
[Your first bundle](#your-first-bundle), and the mt1 strings are the
regtest test transaction of the [`mt` chapter](#mt-mt-cli-reference).
:::

## Conventions

| Topic | Rule |
|---|---|
| What `me` refuses | The converter and `me bundle` refuse every `ms1` (exit 3): a seed is typed on the device (New > Input Seed > CODEX32), never sent by radio. `me bundle` also refuses `mt1` (exit 4): a transaction is not part of a wallet backup, and is packed with `me sysw pack`. `me sysw pack` and `me seal` do accept secret records (`ms1`, BIP-39 phrases), sealed by default |
| Secrets on argv | A secret or bearer record on the command line (a BIP-39 phrase, an `ms1`, a `pass:` record, an `mt1` set, a `tx:` record, a `phrase:` record) is refused **before** the parser runs, by position and never by value (exit 3), on every verb. `--allow-argv-secret` (`sysw pack`, `seal`) proceeds; use it only where argv is not a public channel. Public `md1`/`mk1` records on argv are accepted |
| Output files | `--out` files are created owner-only (`0600`). A stdout that is a group- or world-readable file is refused for the converter's `--stdout`/`--hex`/`--base64` and for `sysw pack` (exit 2) unless `--allow-world-readable` |
| Streams | Payload bytes and JSON go to stdout or `--out`; every warning, checklist, digest and generated passphrase goes to stderr |
| Converter options before a verb | `--in` and `--out` typed before a subcommand (`me --in x.txt bundle`) are honoured as if typed after it, when the verb takes them; a converter-only option there (`me --hex bundle`) is a usage error |

## The converter: `me` with no subcommand {#me-converter}

Turn one public constellation string into an NDEF payload, for a phone
NFC-writer app or the machine's NFC reader. Reads stdin or `--in`. Exactly
one output mode is required.

### Synopsis

```sh
me [--in <FILE>] (--out <FILE> | --stdout | --hex | --base64) [--echo] [--allow-world-readable]
```

### Flags

| Flag | Purpose |
|---|---|
| `--in <FILE>` | Read the input string from this file instead of stdin |
| `--out <FILE>` | Write the NDEF bytes to this file (default: --stdout off => requires --out or an encoding flag) |
| `--stdout` | Write raw NDEF bytes to stdout |
| `--hex` | Print the NDEF bytes as hex on stdout |
| `--base64` | Print the NDEF bytes as base64 on stdout |
| `--echo` | On success, echo the validated md1/mk1 string to stderr (for pasting into a phone NFC-writer app). Off by default |
| `--allow-world-readable` | Proceed even though stdout is a world-readable file (F-244) |
| `-V, --version` | Print version |

### Worked example

```sh
# one-md1.txt holds the first md1 string of the bundle
$ me --in one-md1.txt --base64
A0jRAURUAG1kMWZnZHhscHFwcXBtNmp6enFxdnFwZHF3MHphNXpzNGd5eTU1YXE0dnNtbmh5NHM2d3lheXB1MzRjN3JhcXU4bnD+
$ me --in one-mk1.txt --out mk.ndef
me: wrote 119 NDEF bytes to mk.ndef

$ me --in ms1.txt --hex
me: refusing to emit ms1 over NFC: ms1 is secret seed entropy and must never be transmitted by radio (RF eavesdropping risk). Enter it by hand on the device: New > Input Seed > CODEX32.
$ echo $?
3
```

With no input the converter exits 2 (`me: no input given`); with no
output mode, 2 (`me: choose an output mode`). A wallet descriptor given
to the converter exits 4 and points to `me sysw pack --as`.

## `me bundle`

Validate a wallet backup's public strings and emit a plate manifest +
checklist. The manifest JSON goes to stdout (or `--manifest`), the
checklist to stderr. It admits public md1/mk1 strings only, and every
string must decode: the plate count is a completeness claim, so a plate
that does not decode refuses the bundle instead of being counted.

### Synopsis

```sh
me bundle [--in <FILE>] [--manifest <FILE>] [--preview <DIR> [--png]]
```

### Flags

| Flag | Purpose |
|---|---|
| `--in <FILE>` | Read newline-separated public strings from this file instead of stdin |
| `--manifest <FILE>` | Write the manifest JSON to this file instead of stdout |
| `--preview <DIR>` | Render each public plate to an image in this directory via the `me-preview` sidecar. The sidecar is discovered only alongside the `me` executable; `ME_PREVIEW_BIN=/path/to/me-preview` points at it explicitly. If no sidecar is found, previews are skipped (a note is printed) and the manifest is still emitted |
| `--png` | With --preview, render PNG instead of SVG |

### Worked example

```sh
# bundle.txt holds the three md1 and two mk1 strings of the bundle
$ me bundle --in bundle.txt --manifest manifest.json
warning: this key card's stamped chunk-set id (1c017) was not derived from its content, which computes baa99. ...
me: wrote manifest to manifest.json
me: backup needs 5 public plates, plus one ms1 plate per seed you hold:
  plate 1/5  md1 policy  → push via NFC & engrave
  plate 2/5  md1 policy  → push via NFC & engrave
  plate 3/5  md1 policy  → push via NFC & engrave
  plate 4/5  mk1 [73c5da0a/84'/0'/0'] chunk 1/2  → push via NFC & engrave
  plate 5/5  mk1 [73c5da0a/84'/0'/0'] chunk 2/2  → push via NFC & engrave
  (per seed)  ms1 secret  → TYPE ON DEVICE (New > Input Seed > CODEX32); never via this tool
```

The manifest's `wallet_plates` (6 here) counts the `ms1` plate too. The
chunk-set-id warning is about the mk1 strings, not an error: `mnemonic
bundle` stamps its cards with one shared id, and `me` notes that the id
was not derived from the key data. Exit codes: 2 for no input, 3 for an
`ms1`, 4 for anything else refused (an `mt1`, a plate that does not
decode, an incomplete chunk set).

## `me sysw pack`

Build the systemwide container: a `tx:` record (from `mt encode --qr`)
becomes QR plates, `mt1` strings (from `mt encode`) become transaction
TEXT plates. It also packs wallet-backup strings, a wallet descriptor
(`--as`), BIP-39 phrases and `ms1` strings, free text, and the Wallet
Policy composer's `key:`/`hash:`/`now:`/`phrase:` records.
`me sysw pack --help` defines every record form.

| Record | Class |
|---|---|
| `md1`, `mk1`, `mr1` strings | public |
| `mt1` strings, `tx:<hex>` | bearer (anyone holding them can broadcast), packed in the clear |
| BIP-39 phrase, `ms1`, `pass:<hex>` | secret: the payload is SEALED by default |
| `phrase:<hex>`, an `ms1` kind-`0x03` preimage | bearer hashlock material, admitted only with `--pack-preimage` |
| `text:<hex>`, `key:<hex>`, `hash:[<kind>:]<hex>`, `now:<hex>` | public; prefixed bodies are lowercase hex |

A payload that holds secret material is sealed with a **generated
12-word passphrase**, printed to stderr, unless you choose
`--passphrase-words <N>`, `--passphrase-ask` or `--no-passphrase`. A
payload with no secret record is written in the clear whatever you
choose: an `mt1` or `tx:` payload is bearer and unsealed. Every pack
prints the payload's digest; [`me sysw show`](#me-sysw-show) re-prints
it.

### Synopsis

```sh
me sysw pack [--in <FILE> | <RECORDS>...] [--out <FILE>]
             [--passphrase-words <N> | --passphrase-ask | --no-passphrase] [--iterations <N>]
             [--as <descriptor|md1>] [--expect <KINDS>] [--pack-preimage [--phrase-looks-like-digest-ok]]
             [--now | --no-now] [--region] [--allow-unsigned-inputs]
```

### Flags

| Flag | Purpose |
|---|---|
| `[RECORDS]...` | Records, on argv. argv is a PUBLIC channel — prefer --in or stdin for anything real. A `tx:` record here is REFUSED outright: a raw transaction is a BEARER instrument |
| `--in <FILE>` | Read newline-separated records from this file instead of argv. With neither, records are read from stdin, so `mt encode … \| me sysw pack …` works |
| `--out <FILE>` | Write the blob here instead of stdout |
| `--passphrase-words <N>` | Generate a passphrase of N words (2..=24) |
| `--passphrase-ask` | Prompt for a passphrase on the terminal (with no terminal: exit 2) |
| `--no-passphrase` | No passphrase — the plaintext variant. A secret record then sits in flash in cleartext, with a warning |
| `--allow-weak` | Accepted and ignored. `me` warns rather than refusing (spec §13 D3); kept so existing invocations keep working |
| `--allow-unsigned-inputs` | Admit a `tx:` record with an input carrying NEITHER a scriptSig NOR a witness (FORWARD_PLAN §2.1) |
| `--pack-preimage` | Admit a hashlock PREIMAGE into this payload: an ms1 kind-0x03 plate string, or a `phrase:` record carrying a hashlock phrase and its method |
| `--phrase-looks-like-digest-ok` | Confirm a `phrase:` record whose phrase LOOKS LIKE a digest in hex (F-677, the same flag as `ms hashlock`'s F-539). Without it, a phrase of exactly 40 or 64 hex characters stops the pack (exit 4) |
| `--now` | Append the pack time as a trailing `now:` record to THIS payload even though it holds no `key:`/`hash:` record |
| `--no-now` | Never append the pack time, even when a `key:`/`hash:` record is present |
| `--expect <KINDS>` | Refuse unless the container holds every kind listed here — comma-separated: descriptor, cosigner, transaction, mnemonic, secret. It checks completeness too: a half-transmitted `md1` or `mt1` set fails it |
| `--allow-world-readable` | Proceed even though stdout is a world-readable file (F-244) |
| `--allow-argv-secret` | Proceed even though a record was passed on argv (ruling 2026-08-26) |
| `--iterations <ITERATIONS>` | PBKDF2 rounds [default: 100000]; outside 100000..=2000000 is a usage error |
| `--region` | Pad the container out to a full `REGION_LEN` image (65,536 bytes), ready to write at `0x10D00000`, with `0xFF` (erased flash) |
| `--as <descriptor\|md1>` | How a wallet DESCRIPTOR is packed. Required whenever the input is a descriptor; there is no default and no fallback. `descriptor`: one QR plate any wallet app can scan; `md1`: hand-copyable md1 text cards |

### Worked example

```sh
# A signed transaction, as the mt1 strings mt encode wrote:
$ me sysw pack --no-passphrase --in strings.txt --out tx-text.bin
sealing:  NOT SEALED — no record in this payload is secret material, so there
      is nothing to encrypt. The container is cleartext: anyone holding the file
      can read it.
strength: no passphrase — BELOW the threshold
digest:   d8d4 85bd c212 5bf2 5df1 25f0 c693 da40
          re-print it with: me sysw show tx-text.bin

# The same transaction as QR plates, straight from mt:
$ mt encode --qr --in tx.psbt.b64 --bitcoin-cli /nonexistent 2>/dev/null \
    | me sysw pack --no-passphrase --out tx-qr.bin
...
digest:   3269 0280 306c cb2a 9e4a 8df3 6f7e 1a0c

# A wallet backup that must hold its cosigner cards:
$ me sysw pack --no-passphrase --expect descriptor,cosigner --in md1-only.txt --out backup.bin
me: --expect cosigner was not met: NO record of that kind is in the stream.
      Looking for an mk1 cosigner card.
      Nothing was written -- ...
$ echo $?
4

# A seed phrase: sealed, with a generated passphrase on stderr
$ me sysw pack --in phrase.txt --out seed.bin
sealing:  SEALED — this payload holds secret material (record 0 (BIP-39 mnemonic)), so it is encrypted
      and opens only with the passphrase below. ...
passphrase — write this down and store it APART from the machine:

    <twelve generated words>

strength: 12 words — at or above the threshold
digest:   none — this payload has no public section
```

A descriptor file (`wallet.txt`) packs with `--as descriptor` or `--as
md1`; without `--as` the pack stops (exit 2) and explains both. `me sysw
pack` prints what it read the descriptor as, its first address and its
wallet id, so you can compare them with your wallet software before
engraving. For a hashlock preimage, see
[Getting a preimage INTO a payload](#getting-a-preimage-into-a-payload-me-sysw-pack---pack-preimage).

## `me sysw wipe`

Emit a full-region overwrite image (spec §5.5): 65,536 bytes, to
`--out` or stdout.

### Synopsis

```sh
me sysw wipe [--out <FILE>] [--fill <random|zeros|ones>]
```

### Flags

| Flag | Purpose |
|---|---|
| `--out <FILE>` | Write the image here (`0600`) instead of stdout. `me sysw wipe --help` gives this flag no description |
| `--fill <FILL>` | random (default), zeros, or ones. NOTE: ones is the ERASED state of NOR flash, so that region is indistinguishable from one never written [default: random] |

### Worked example

```sh
$ me sysw wipe --fill ones --out wipe.bin
me: note — 0xFF is the ERASED state of NOR flash, so this region will be indistinguishable from one that was never written
```

## `me sysw show`

Print what a container holds, and its digest. Secret records are named
by class, never shown.

### Synopsis

```sh
me sysw show <FILE>
```

### Worked example

```sh
$ me sysw show tx-text.bin
sealed:   false
pub_len:  795
ct_len:   0
identity: 637cedeff20cad8150053e058ef9fb50fe1618d6e85da756cd311212b60b4639
digest:   d8d4 85bd c212 5bf2 5df1 25f0 c693 da40
public record 0: mt1 chunk — confirmed
...
public record 8: mt1 chunk — confirmed
  mt set 4665e: txid 4665e0aa2a97dee3e53fd2eaab0942abc0fef2339e730458ceedcda400d708c3 — 339 bytes, 2 input(s), 1 output(s), 9 string(s)
```

The `digest:` line is on stderr, the rest on stdout. A file that is not
a systemwide container exits 4 (`BadMagic`); a missing file exits 2.

## `me seal`

Encrypt a payload for delivery to SeedHammer II flash, as a UF2 image
to load with `picotool` (machine in BOOTSEL). The passphrase is
GENERATED and printed to STDERR; there is deliberately no way to supply
your own.

### Synopsis

```sh
me seal --out <OUT> [--seal-secret] [--in <IN_PATH> | <PAYLOAD>...] [--plaintext <PLAINTEXT>]... [--iterations <N>]
```

### Flags

| Flag | Purpose |
|---|---|
| `[PAYLOAD]...` | Records to ENCRYPT, on argv. Kept for FIXTURES AND TESTS only; a secret record there is refused (see Conventions) |
| `--in <IN_PATH>` | Read newline-separated records to ENCRYPT from this file, or from stdin when neither this nor argv records are given |
| `--plaintext <PLAINTEXT>` | Records to carry in the CLEAR. Authenticated via the AAD when something is also encrypted; unauthenticated otherwise. Never an ms1 or a BIP-39 mnemonic. Repeatable; together they must form a decodable card set (exit 4 otherwise) |
| `--out <OUT>` | Write the UF2 here. Created 0600. REQUIRED — never stdout, because the passphrase shares that stream |
| `--seal-secret` | Required to encrypt seed material — an ms1 record or a BIP-39 mnemonic (exit 3 without it) |
| `--allow-argv-secret` | Proceed even though a record on ARGV is secret or bearer material |
| `--iterations <ITERATIONS>` | PBKDF2 iterations. 300,000 = 30.9 s on device [default: 300000] |

### Worked example

```sh
$ me seal --seal-secret --in phrase.txt \
    --plaintext md1fgdxlpqpqpm6jzzqqvqpdqw0za5zs4gyy55aq4vsmnhy4s6wyaypu34c7raqu8np \
    --plaintext md1fgdxlpqf2zcgefcpupmel75q5435j7seugaj5jr7qyur6vt76es5cdeyrq7zdy0d \
    --plaintext md1fgdxlpq3xa2dk8vwpj7gx74hwqxqdp083jehp5tdrfa0n5zdfkqcdlrvnh5r62jn \
    --plaintext mk1qprsqhpqqsq3cqtsleeutks2qvzg3vs70mejhk622ws2kgdemj2cd8zwj2skzx2wq0qw70l4q99vdyh5x0z8v4yslsp8qp3yxg3dpe854wq4 \
    --plaintext mk1qprsqhpp0f30mtxzd65mvwcur9usdatwuqvq6z70r9nwrgk6xn6l8gy6nwa2n977sw6zh34rma0nh \
    --out sealed.uf2
...
me: wrote 1536 bytes to sealed.uf2

public data hash (5 records, SEALED):
    e5ca 1363 b7b9 4785 e6fe 8872 b780 f684
RECORD THIS WHOLE LINE. The device shows the same value; if it
differs, the payload has been altered or its encryption removed.

passphrase — write this down and store it APART from the machine:

    <generated words>

load:  picotool load --verify sealed.uf2   (machine in BOOTSEL)
wipe:  picotool erase -r 0x10E00000 0x10E10000
```

## `me hash`

Re-derive the §6.6 public-data hash from your own cards — no
passphrase, no seal operation, no original file — to compare months
later with what the device displays.

### Synopsis

```sh
me hash (--sealed | --unsealed) [RECORDS]...
```

### Flags

| Flag | Purpose |
|---|---|
| `[RECORDS]...` | The public records, in order |
| `--sealed` | The payload was sealed (carries an encrypted section) |
| `--unsealed` | The payload carries no encrypted section |

Exactly one of `--sealed` and `--unsealed` is required (exit 2
otherwise).

### Worked example

```sh
$ me hash --sealed $(cat md1.txt mk1.txt) 2>/dev/null
e5ca 1363 b7b9 4785 e6fe 8872 b780 f684
```

It matches the hash `me seal` printed above.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | success |
| `1` | a write to stdout failed (`me: cannot write the output: <error>`, e.g. a full disk) |
| `2` | usage: the invocation is wrong and nothing about the data was judged (an unknown flag, no input, no output mode, a world-readable stdout, `--iterations` out of range, a missing `--as`, a file that cannot be read) |
| `3` | policy refusal: understood and refused on purpose (an `ms1` to the converter or `bundle`, a secret or bearer record on argv, seed material to `seal` without `--seal-secret`) |
| `4` | invalid: the input is not what it must be (a string that does not decode, an `mt1` to `bundle`, an unmet `--expect`, a digest-shaped `phrase:` without `--phrase-looks-like-digest-ok`, a file that is not a container) |

A reader that closes the stdout pipe early only stops the output: the
exit code is the verb's own. These are the codes of `me 0.13.0`; they
change when the constellation's shared exit-code scheme
(mnemonic-engrave PR #69) lands.

## Quirks

- `me --echo` labels every string it echoes `md1` unless it starts
  with `mk1`: for an `mt1` string it prints
  `me: validated md1: mt1…`. The converter accepts `mt1` although
  `--echo`'s help names only md1/mk1, and the echoed `mt1` is bearer
  material on stderr.
- The converter and `me bundle` refuse `ms1` (exit 3), but `me bundle`
  refuses `mt1` with exit 4, not 3.
- The chunk-set-id warning on `mnemonic bundle`'s mk1 cards prints once
  per reading: `me sysw pack` prints it twice for one input.
- If stderr is a pipe that closes early (`me sysw pack … 2>&1 | head
  -1`), `me` exits 101 instead of its own code; the payload is still
  written.
